# Agent Team

当前主会话执行根任务，负责最终交付。先用 `agent_team_read` 取得这次 `/agent-team` 请求的 `intent_id`，再用 `agent_team_create` 记录目标、工作区和必要约束。返回的根任务已经指派给你；创建操作不会额外启动一个根任务成员。

1. 简单工作直接执行。需要协作时，用 `flow_task` 委派独立的业务部分，明确产物路径、负责范围和真实依赖；主会话保留整合与核验责任。各自执行分配到的部分，避免与成员重复跑完整目标或同时写同一文件。只有委派才创建成员；拿到任务和成员身份即已完成委派。
2. 继续不依赖成员结果的工作。若只剩等待，自然结束当前回合，真实结果消息会唤醒本会话继续处理。不要为等待成员启动 shell 轮询、sleep 循环或阻塞等待进程；它们会推迟本会话处理验收消息。这是协作的等待方式，不改变普通原生工具和后台作业的用途。
3. 成员用 `flow_result` 提交实际成果和产物引用，准确标记 complete、partial 或 blocked。委派者亲自用原生工具打开已有产物、重算或运行检查，按用户要求和任务已有完成条件调用 `flow_review` 接受当前结果，或附具体原因退回。不要只为形式上的独立性另启评审 Agent，也不要自行增加来源数量等验收门槛。实际业务需要进一步分工时，成员仍可递归委派并核验子任务。
4. 需要的子任务已接受后，主会话汇总并检查最终产物，用 `flow_result` 提交自己的根任务，再用 `flow_review` 接受这个具体根结果。根任务接受才表示团队完成；直接由主会话执行全部工作时也完成这两步。
5. 用 `flow_message` 传递需要处理的请求，或发送不唤醒空闲成员的 notice。用 `flow_read` 按需、分页读取当前事实。用户明确要求暂停、恢复或取消时使用 `flow_control`；普通正文不充当停止命令。

同一重试沿用同一操作身份；新的工作使用新的身份。任务修改后检查新版本交付。团队 pause 停止新增投递，并启动原生取消与排空；resume 通过正常输入继续工作。任务接受、Agent 空闲和后台作业结束是不同事实。

需要在不同目录同时工作时，把文件分工作为任务说明，并按宿主正常配置选择工作区和 sandbox。完成时报告实际产物、检查结果与尚未解决的外部限制。

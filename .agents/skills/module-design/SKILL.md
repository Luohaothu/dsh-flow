# 模块设计方案

适用于用户已指明模块或已选定改进项的设计讨论。用户给出的语言、结构、场景和职责划分优先；仓库范围内的选题扫描继续使用原有架构探索流程。

## 工作步骤

1. **固定范围。** 从当前对话确认目标模块、直接调用关系和已确定的职责。以这些内容作为方案范围；只有用户要求时才增加其他模块、异常恢复或反面案例。
2. **核对现状。** 遵循仓库 `AGENTS.md` 的资料导航，定位目标模块的实现与直接调用方。记录足以说明问题的代码位置；将当前行为与建议行为明确区分。
3. **完成设计。** 用少量明确概念串起问题原因、职责划分和交互过程。只展开用户场景涉及的接口与主流程；源码已有的异常、重试、关闭等分支不因存在就自动纳入范围。架构图、接口及伪代码表达同一组对象和调用关系。用户尚未确定的选择保持为建议，不写成既定要求。
4. **形成方案。** 默认使用专业中文和下述五部分。代码标识保留源码名称，正文用中文说明含义。图表放入对应章节。
5. **核验交付。** 用随附脚本检查章节与顺序，再逐段检查是否直接支撑用户场景，并核对接口和伪代码是否一致。HTML 方案还须实际渲染，确认图示和代码可读。

## 默认结构

方案只包含以下五个正文一级章节，按此顺序排列；章节内按需使用小标题。

1. **问题分析**：目标模块当前承担什么职责，哪些职责相互依赖，以及这种依赖产生的直接影响。
2. **概念设计/架构设计**：必要概念、职责归属、对象关系和主要交互；架构图放在本节。
3. **接口设计**：接口所属对象、输入、输出和异步操作的完成含义；UML 类图放在本节。
4. **伪代码实现/应用实现**：沿用户给定场景展示主要调用链；伪代码与 UML 时序图放在本节。
5. **实施安排**：按依赖关系列出迁移步骤、形成的结果和与该模块直接相关的验证。

默认结构适用于 Markdown 和 HTML，不增加独立摘要、比较、附录或额外分析章节。用户明确调整结构时，使用其指定章节，并将验证、取舍等必要内容放入对应章节。

## 章节校验

Markdown 用 `##` 表示五个正文一级章节。HTML 的 `main` 内用 `h2` 表示对应章节。页面标题、导航及章节内的 `h3` 不算额外正文一级章节。

在仓库根目录运行：

```sh
python3 .agents/skills/module-design/scripts/check_sections.py <方案文件>
```

用户指定其他章节时，以实际标题覆盖默认列表：

```sh
python3 .agents/skills/module-design/scripts/check_sections.py <方案文件> --sections "章节一" "章节二"
```

脚本只验证章节结构。内容范围、概念准确性和跨图表一致性由设计与审查过程核验。

# 标准 Agent：最小协作机制

以确定性的协议、状态不变量和失败恢复验证机制简洁性，不以模型生成的报告、分工、来源数量或耗时排名判断设计优劣。结果见[实施验证](native-agent-simplification-validation.md)。

此前严格模型对照方案、观察草稿和原始登记保留在[归档](archive/2026-10-13/README.md)。方向调整后模型实验安全中止，后续阶段未启动；没有完整优化配对，不宣称速度提升。

## 第一性原理

执行实现的调度单位是标准原生 Agent。协调者和执行者是用户可见的两类通用角色；资源分配归入协调者，研究等属于具体职责，通过派发参数、原生 preset、模型、系统提示和 skills 配置实现。角色不是不同的执行器，也不是权限等级。模型、工具、权限、Inbox、回合、取消和持久化由 DSH 管理。Flow 只表达谁委派给谁、交付是否就绪、委派者是否接受，以及根任务是否明确完成。

一次正常协作需要四类事实：委派、成果发布、委派者决定、主会话完成。已有标准 Agent 的自然最终返回可以发布成果；创建团队、重复确认和本人自验收没有新增业务信息，应从模型交互中删除。

## 当前路径

/agent-team 按稳定提交身份直接建立团队和主会话持有的根任务，再投递一次正常原生输入。创建不另启根成员，不让模型读取意图再创建。原生附件准入开启；热/冷重复不多建团队或输入，不同正文或附件仍拒绝。

主会话承担协调者职责，成员通过 `flow_task.profile` 声明角色和配置，界面展示对应职责。主会话和成员统一使用六类 flow 工具。四个 agent_team_* 模型入口、重复 criteria、预声明 depends_on 及 parent_task_id 已删除，无兼容分支。要求只有 objective；父任务由调用 Agent 当前任务确定，成员仍可递归委派和复用。

Agent 收到真实前置交付后再委派业务，不由 Flow 预建等待图。删除声明依赖可消除“子任务等待祖先、祖先等待子任务验收”的结构性环路，也不需要再增加图循环检测平台。

同一 Agent 仍只执行一个原生活动，待派发任务按稳定行序选择。上一成果尚未验收不阻塞下一独立任务，暂停某项工作也不阻塞其余独立工作。修改排队任务只检查该任务是否活跃，不要求暂停正在做另一任务的 Agent。

成员简短自然最终返回在 idle、flush 和再次空闲检查后发布；明确 partial/blocked 保留结构化 outcome，不被最终正文覆盖。委派者亲自用原生能力检查，并对当前具体结果接受或退回。

主会话用一次根 flow_result complete 完成团队。结果、根 ACCEPTED 和团队 completed 同事务写入；未接受或取消的子任务原子阻止完成。无需自验收或 finalize。终态只回收 Flow 创建的成员，主会话继续由宿主管理。

task/result/review/message 返回后续操作所需身份、版本与状态，不回显刚提交的长正文。完整事实仍从持久化记录、read 和界面读取。read、消息和控制用于实际需要，不是正常路径必经确认。

## 必要守卫和验证边界

保留真实 actor、任务版本、当前结果、合法委派者、子任务义务、操作幂等和原生持久化顺序。它们保护并发事实一致性，不按角色名称分支执行，不增加能力裁剪或业务质量门槛。

验证采用真实 Controller/SQLite 的有界状态切面、故障注入和固定脚本模型的真实原生链路。检查零副作用拒绝、一次输入、最少协议调用、互斥与异步排空；不把实例测试说成无限状态证明，也不证明业务文件或模型判断正确。

当前数据格式 schema 8，旧 schema 5/6/7 明确拒绝。部署使用新的 Flow dataDir，原生历史、模型配置与凭据独立保留。

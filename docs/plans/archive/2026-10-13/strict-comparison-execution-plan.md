# 标准 Agent 协作交互精简

本轮在 `2236cab` 标准 Agent 实现上继续减少模型往返，并以相同模型、任务和验收标准开展单 Agent / 团队严格对照。代码优化已完成，实际对照与验证仍在执行；最终数据见[实施验证](native-agent-simplification-validation.md)。

此前精简方案和上轮验证已原样进入 [2026-10-13 归档](archive/2026-10-13/native-agent-simplification-plan.md)。其中“模型读取意图后创建团队”和“根结果再由本人 flow_review”的步骤不再是当前指令。固定角色、权限裁剪、工具门禁、预算、租约和强制计划仍保持删除。

## 当前执行方式

`/agent-team` 命令按稳定提交身份直接建立团队和已有主会话持有的根任务，然后投递一次正常原生输入。创建不启动后台根成员。原生附件准入显式开启；同一提交的正文或附件冲突拒绝，热/冷重复不会多建团队或输入。

主会话和成员统一使用六类 `flow_task/result/review/message/read/control` 工具。四个 `agent_team_*` 模型工具及其代码已删除，不保留别名入口。团队历史枚举和会话导航仍由原生界面及只读 Web 接口提供；模型 `flow_read` 读取当前或明确指定团队。

删除重复的 criteria 输入、任务字段和注入模板，工作与交付要求统一放在 objective 内。识别可以独立开始的业务后立即委派互补工作，再做自己的部分。任务说明给出实际依赖、产物与负责人；达到用户原要求即可收束。核验使用已保存的产物和真实回执，缺证据或有矛盾时再采集。

成员一次简短自然最终返回可由既有 native-return 发布为交付；明确 partial/blocked 或需要结构化引用时调用 `flow_result`。已有显式结果不被最后正文覆盖。发布仍等待原生 idle 与持久化 flush，不能提前 ready；委派者实际检查后以 `flow_review` 接受或退回。

已有主会话完成最终检查后，用一次根 `flow_result outcome=complete` 明确完成团队。结果、根 ACCEPTED 和团队 completed 在同一事务中写入；必要子任务未接受或取消时原子拒绝。根 partial/blocked 保持未完成。本人完成声明不伪造 Review；团队终态只回收 Flow 创建的成员，主会话继续由 DSH 执行。

## 保留的原生和业务边界

原生 preset、工具、sandbox、审批、模型、Inbox、Jobs、取消与会话持久化不裁剪。Flow 成员身份用于 `flow_message`；原生 continuable subagent 的身份继续使用原生通信工具，公开描述区分两者，不加权限过滤。

任务版本、真实作者/委派者授权、具体结果接受、命令幂等、自然返回的持久化边界和取消排空保留。普通等待通过自然返回与真实结果消息推进，不新增模型调度员或通知恢复平台。

## 严格对照协议

两个版本各两对，串行反序 `O1 → T1 → T2 → O2`，共八个前瞻登记阶段。共同业务提示逐字相同、固定日期 2026-10-12；模式只区分当前单 Agent 禁止委派与 Flow 团队至少一次真实业务委派，不规定成员人数或层级。

每版本冻结可安装包；每阶段使用全新 HOME、工作区和 Flow 数据。固定已配置 `qwen-token-plan-cn / deepseek-v4.1-flash / max`、`standard`、原生 `workspace-write / ask`。实际 request/header、工具目录、权限、日志及产物哈希校验；不只相信配置声明。

失败、中断和质量问题全部保留，不选择性重试、不补提示或原位修正报告。任务墙钟、模型生成、业务工具、纯协作步骤、通知回合、重复取数、真实 usage 和交付质量分别报告。标题模型调用若缺 usage 则标未知，不把会话聚合当全部账单。来源网络、提供方缓存和负载不能完全控制，两对只支持描述性结论。

共同验收检查三指数的日期、收盘和涨跌幅、实际 HTTP 与 raw、两个交付文件、引用与限制说明。成交额/广度不是新增必做门槛；主动写入的额外数字错误仍记录。报告字数和固定来源数不作为业务质量要求。

当前 Flow 数据格式为 schema 7，明确拒绝旧 schema 6；不迁移或重演旧任务。部署使用新的 Flow dataDir，原生会话、Provider 与凭据保持独立保存。

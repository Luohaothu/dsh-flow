状态：运行中。基线为 `2236cab`；优化源码尚未提交，版本身份以冻结安装包和源码指纹为准。完整八段封存及独立质量检查完成后，再填写优化效果。

## 对照方法

共同业务任务固定为 2026-10-12 A 股复盘，提示逐字相同，SHA-256 为 `e688cfa644610cce4d904eab5daf5aa8ef864e195a926db7a07a02812ca34cea`。要求实际 HTTP 采集、保存 raw、验证三指数收盘和涨跌幅、交付 report.md 与 market-data.json、检查产物，并只在工作区写入。成交额、市场广度和来源数量没有额外必做门槛；主动添加的错误数字仍作为质量问题记录。

每个版本按 `O1 → T1 → T2 → O2` 串行执行两对反序样本，共八段。每段使用全新 HOME、工作区和 Flow 数据，冻结可安装包、实际运行依赖、共同提示、模式提示和配置指纹。单 Agent 模式禁止委派；团队模式要求至少一次真实业务委派，成员数与分工由模型决定。两个版本使用同一配置字节和 `qwen-token-plan-cn / deepseek-v4.1-flash / max`，实际 request/header 核验模型、推理级别、standard preset 及原生 workspace-write/ask。

所有首轮结果、超时、失败和质量问题留在原分母中，不选择性重试、补提示或修改报告。每段上限 30 分钟是实验终止条件，没有增加产品预算机制。计时从用户输入派发到自然完成被观测，另记 runner 总时间和原生日志边界。工具 call→receipt 延迟不能当作 CPU 时间，并行 Agent 的生成时长之和不能直接从墙钟扣除。

网络、提供方负载及缓存不能完全冻结，实际 cache usage 分别记录。标题模型请求若没有 usage，其费用保持未知，不把会话 usage 说成全部账单。普通输入含 clientTimeZone 元数据、命令输入只有 user source；实际适配器只发送正文，全部已核验会话没有加载时间上下文注入。仍保留这一输入元数据差异，并区分 skill/协作上下文这一有意处理变量。

独立验收同时查看产物语义、日期、价格、涨跌幅、单位、来源 URL/日期、真实 HTTP 回执和写入范围。产物存在、原生自然结束、Flow ACCEPTED 与实验质量通过分别表达。脚本首次失败后在同一正常回合内自行修复属于真实执行过程；实验人员不修复交付。

## 基线定位

第一对 O1 用时 398.770 秒，T1 用时 1052.349 秒，团队额外 653.579 秒，约为单 Agent 的 2.64 倍。O1 为 41 次模型响应、52 次工具调用；T1 为 155 次响应、177 次调用。这一比例只描述该对自然执行结束时间，两组都存在工作区外写入，T1 还有单位和引用问题，不能描述成相同质量的完成速度。

T1 的 15 次 Flow 控制调用从 call 到 receipt 合计 130 毫秒；10 个纯协作模型步骤合计 150.333 Agent 秒。首个实际委派晚于输入约 101 秒，之前主 Agent 已做九次 bash 探测。团队自己增加了串行“独立数字复核”任务和不同来源数量门槛，复核成员连续执行约 510 秒，并晚于其他必要采集成员 189 秒完成。两次大段脚本重写因相同文件名问题失败，消耗约 161 Agent 秒。显式结果又生成长篇摘要并重复最终返回。三个结果通知触发两个主会话续回合，没有发现通知风暴或调度死锁。

T2 自然结束用时 1792.967 秒，195 次模型响应、232 次工具调用。两个成员没有串行依赖，关键路径仍是约 1424 秒的行情背景成员：自行扩展到 42 个板块、海外市场及 13 日盘中材料。主 Agent 同时重复采集了已经委派出去的三指数业务。最后成功网络抓取之后，成员仍用约 640 秒整理登记、长文与引用。主 Agent 等待期间成员实际工作，不能把这段时间都算作调度空转。

基线可见的额外调用有三类。其一是重复协作入口、重复正文回显和根结果自验收造成的模型往返。其二是模型主动增加业务范围、形式独立复核和重复采集。其三是原生工具使用问题：未配置搜索服务密钥、把 Flow 成员 ID 用于原生 continuable 通信，以及自行 bash 修改文件后被 edit 的过期读取保护拒绝。后者需要区分使用方法与宿主能力，不能通过裁剪正常原生工具或关闭版本保护掩盖。

O1 的三指数核心数据可核实，但日期概述有误且写入 /tmp。T1 核心数据正确，九个成交量单元格约低 100 倍，20 个引用 URL 有误，旧材料日期和独立覆盖声明不实，也存在 /tmp 写入。T2 已发现 /tmp 采集脚本及文件，并在最终自述中声称只写工作区；完整质量记录继续独立核对。

## 精简改动与验证

命令按稳定提交身份直接创建团队和已有主会话持有的根任务，随后仅投递一次正常原生输入；不再让模型读意图再决定如何创建。删除四个 agent_team_* 模型工具与实现，主会话和成员统一使用六个 flow 工具。原生附件准入、热/冷重复提交及正文/附件冲突经过实际原生链路检查。

根完成改为一次明确 flow_result complete，在同一事务写入结果、根 ACCEPTED 与团队 completed；不产生自验收 Review。未接受或取消的必要子任务仍阻止完成，partial/blocked 保持未完成。成员使用简短自然最终返回，明确受阻或结构化交付时保留显式结果，idle/flush 与实际委派者接受边界继续存在。

删除重复 criteria 字段和注入模板，要求统一放在 objective。task/result/review/message 返回后续操作所需身份、版本或状态收据，完整事实仍持久化。指南要求尽早委派互补工作、同一产物明确写入负责人、用已有回执核验并按用户原要求收束；不增加来源配额、角色、权限门禁或工具过滤。

数据库变为 schema 7，旧格式明确拒绝，部署另用新 Flow dataDir。原生模型、权限、工具、会话和凭据保持由宿主管理。单元回归和完整构建已通过，最终实际原生检查、八段质量结果、效果表及交付身份待封存后补齐。

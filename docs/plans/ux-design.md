## 1. 范围、原则与页面库存

### 1.1 已确认的产品边界

- dsh-flow 是标准插件，安装后显示在宿主插件管理页面，并具有独立的插件设置页。
- 用户通过主会话输入 `/agent-team` 加自然语言需求来启动团队；样例统一为“为知识库增加全文检索”。
- 主界面保持宿主原有结构，仅增加一个“智能体团队”顶栏按钮和与“对话”“轨迹”并列的“智能体”标签页。
- 不增加“X 个子智能体”独立下拉入口，不替换主输入框，不增加另一个团队指令系统。
- 智能体视图和检查器只读：允许查看、搜索、筛选、导航、复制和调整显示；团队生命周期指令在主会话下达，完整子会话允许给未回收的代理发送补充消息。
- 节点、通信详情和检查器不提供执行操作。完整原生子会话允许给未回收的代理发送消息、停止当前轮次；团队生命周期操作仍由主会话处理。
- 预算本次只展示服务提供的额度信息；不提供额度设置、追加、调整或预算阈值策略。
- 回收表示运行资源已释放，不删除代理的历史节点、会话、通信和计量记录。
- 插件设置只影响显示，不改变任务的执行、调度、预算或权限。
- 原有 dsh-flow 界面元素及交互逻辑均已废止；本次按当前文档重新确定页面与流程，不并行保留旧界面或兼容入口。具体废止规则见 1.5。

### 1.2 P0 体验目标

用户应当能够回答四个问题：团队正在做什么、谁正在处理、谁在等待什么、结果在哪里。P0 优先保证这些信息的一致、可读和可追溯；动态效果不得阻碍阅读。

P0 包含全部页面的基本展示、正常与异常状态、只读联动、实时同步、键盘访问和响应式布局。动画采用简单过渡即可，不以复杂物理布局或持续装饰性动画作为交付条件。

### 1.4 实现优先级与官方参考

- **产品语义保持一致**：唯一团队入口、只读观察、主会话管理团队、原生子会话续聊、预算仅展示等已确认要求必须保留；参考官方实现不意味着增加平行的子智能体下拉。
- **官方 UI/UX 优先**：有对应官方实现时，优先参考其组件组合、信息层级、导航、键盘操作、状态反馈和交互惯例；可复用的公开组件或扩展能力优先直接复用。
- **按界面归属创建**：区域由 dsh 管理时，使用 dsh 的对应接口；由其他 UI 插件管理时，使用该插件的对应接口。注册入口、传入数据或提交内容，由提供方创建和管理相应界面，不在 dsh-flow 中另画一个相同的外壳。
- **样式由实际提供方控制**：容器大小、停靠方式、主题、字体、间距、断点、层级、焦点与动效优先沿用对应组件的规则和配置。不得为贴合示意图而覆盖宿主或其他 UI 插件的全局样式。
- **自定义仅补充业务差异**：确无可复用内容组件时，可在获准的扩展区域内实现团队拓扑、状态标记等专属内容；外围页面、标签、面板和会话仍使用对应接口。不能将“内容需自定义”扩大为重绘整个宿主界面。
- **接口缺口明确记录**：开发时核对官方来源、适用版本、界面提供方与公开接口。若缺少所需接口，记录缺口并设计适配或接口扩展；不得把原型 DOM、截图坐标、私有结构或 CSS 覆盖当成生产接入方式。

上述规则适用于全部页面和补图。第 3 节的数值用于沟通信息密度与相对布局；验收关注业务语义、可用性和与宿主的一致性，不要求与设计图逐像素相同。本次修订规定参考与复用原则，不声称已经核实具体官方接口名称或版本。

### 1.5 当前文档权威与旧 UI/UX 废止

当前文档是 dsh-flow 页面形态、入口、信息架构、状态呈现和交互逻辑的唯一设计依据。旧方案和现有实现中未按本文重新定义的 UI/UX 不再生效，不因为已经存在代码、文档或用户入口而自动成为新设计的兼容要求。

| 已废止对象 | 废止范围 | 本次设计依据 |
|---|---|---|
| Cluster panel | 原面板、打开入口、面板内界面元素及其交互逻辑 | 本文 S04 团队树、S05 智能体标签及 S06 只读联动详情；不保留平行的旧面板 |
| 集群模式 profile | 原模式配置入口、模式选择 / 切换逻辑及其作为团队启动前提的流程 | 本文 S03 的 `/agent-team` 加自然语言启动；用户无需选择旧集群模式 profile |
| 其他旧 dsh-flow 界面元素与交互 | 旧页面、菜单、按钮、标签、配置界面、快捷入口及其操作路径 | 仅按本文重新定义的界面与行为实施，不从旧实现自行补回 |

- 新设计只复用经核实适用的组件和接口；不继承这些组件此前承载的旧产品流程。
- 若旧实现、旧规划或官方示例的产品行为与本文冲突，以本文为准。官方参考不能引入旧 Cluster panel、集群模式 profile、额外子智能体下拉或直接控制智能体的操作。
- 生产接入时应清理旧 UI 的注册入口和交互绑定，不通过隐藏开关、别名入口或旧模式切换继续暴露已废止流程；对旧入口引用给出失效说明或指向本文对应的新入口，不重新激活旧 UI。
- 宿主及其他 UI 插件负责的通用界面仍按 1.4 与 3.3 通过其接口创建；“复用提供方组件”不等于“保留旧 dsh-flow 界面”。
- 本节废止的是界面设计及交互契约；底层执行能力、历史数据和存储的处理应在相应实现方案中另行界定，不能仅因 UI 废止而推导删除历史记录。

## 2. 主流程与导航

```mermaid
flowchart TD
    A[安装并启用 dsh-flow] --> B[主会话输入 /agent-team 和需求]
    B --> S[加载 skill：主 Agent 评估需求并生成参数]
    S --> T[主会话调用 create 并用 read 检查]
    T --> C{启动结果}
    C -->|成功| D[主会话出现团队按钮和智能体标签]
    C -->|失败| E[保留原输入并显示启动失败]
    E --> B
    D --> F[悬浮或点击团队按钮]
    F --> G[紧凑派生树]
    G --> H[子代理完整会话]
    H --> D
    D --> I[智能体标签：拓扑或列表]
    I --> J[选中代理]
    J --> K[画布上悬浮的对话与信息]
    K --> H
    I --> L[选择通信记录]
    L --> M[通信详情]
    I --> N{团队进展}
    N -->|需要用户答复| O[定位等待原因]
    O --> P[回主会话答复]
    P --> D
    N -->|结束| Q[保留拓扑、结果、会话与通信历史]
```

### 2.1 导航约束

- 每个团队归属于一个主会话；查看期间始终能识别当前主会话与团队。
- 同一主会话如存在多次团队运行，页面标题区通过“运行记录”选择已发生的运行；顶栏仍只有一个团队按钮。
- 默认展示当前运行；没有当前运行时展示最近一次。切换运行属于查看操作，不启动或恢复任务。
- 运行记录仅在确有多次运行时出现；不为单次运行增加空入口。
- 从顶栏树点击代理标题，进入 S07；从拓扑或列表选择节点，进入 S06，不跳离当前主会话。
- S07 提供所属“主会话”入口和团队下拉；返回主会话保留原标签、画布视角、所选代理和阅读位置。
- S06 的“打开完整会话”导航到 S07；详情中的父代理 / 子代理链接只改变当前选择。
- S08 的发送方 / 接收方链接定位并选中对应代理；关闭通信详情恢复此前的节点选择。
- 切换“对话 / 轨迹 / 智能体”不重启任务，不清空智能体页的本地查看状态。
- 浏览器或宿主返回动作遵循原导航语义；插件不截获与本功能无关的快捷键。

### 2.2 统一设计样例

| 代理 | 标识 | 父代理 | 状态 | 累计 Token（自身） | 样例职责 |
|---|---|---|---|---|---|
| 总协调 | `lead` | 无 | 运行中 | 12,840 | 分解需求、协调实现与汇总 |
| 需求分析 | `research` | `lead` | 已完成 | 8,620 | 明确全文检索的使用场景 |
| 检索实现 | `search` | `lead` | 运行中 | 17,300 | 实现索引与查询逻辑 |
| 界面实现 | `ui` | `lead` | 等待用户 | 4,200 | 等待确认结果摘要形式 |
| 质量验证 | `qa` | `search` | 等待其他智能体 | 5,300 | 等待检索实现可验证 |

样例团队共 5 个智能体，计数包含总协调根代理；不引入额外角色分类。样例任务已运行 `08:42`（8 分 42 秒），累计 Token 为 `48,260`，等于上表各代理自身用量之和。预算样例只在检索实现详情展示 `120,000 Token · 当前代理独立额度`，不表示团队共享额度或任何实际分配算法。

“等待用户”的代理不会单独获得输入框。样例问题为“结果摘要需要包含上下文吗？”，由用户回到主会话答复。

## 3. 全局布局与视觉规范

### 3.1 尺寸与区域

**本节和后文出现的全部布局数值仅供参考。** 图注中的画板尺寸仅是设计图片的导出规格。实际实现根据 dsh 或相应 UI 插件提供的容器尺寸、布局接口、主题与响应式规则适配，不硬编码宿主栏位的宽高，也不以整个应用窗口宽度代替插件实际可用宽度。

| 项目 | 图稿参考值 / 预期行为 |
|---|---|
| 主设计画板 | 1440 × 900 px；仅为截图规格，不要求页面固定宽高 |
| 宿主左侧栏 | 参考 224 px；由宿主管理，插件不创建或锁定其尺寸 |
| 主会话顶栏 | 参考 64 px；通过顶栏扩展入口加入团队按钮，由提供方排列 |
| 页面标签栏 | 参考 48 px；通过标签扩展入口加入“智能体”，与“对话”“轨迹”同层 |
| 主内容边距 | 参考桌面 24 px、紧凑视口 16 px、手机 12 px；实际使用提供方的间距规范 |
| 节点 | 参考 220 × 100 px，水平间距 40 px、层级间距 64 px；随内容、字体和图布局调整，保持可读与不重叠 |
| 右侧信息面板 | 参考 320 px；使用提供方的面板容器及滚动行为 |
| 悬浮详情容器 | 初始高度约为内容区的 45%，可读下限 220 px；采用提供方的分隔与尺寸约束，可关闭或调整尺寸 |
| 宽桌面 | 参考 ≥1280 px；可用空间充足时在悬浮容器中并列展示对话与信息 |
| 紧凑桌面 | 参考 768–1279 px；空间不足时使用单个详情容器，以“对话 / 信息”切换 |
| 手机 | 参考 <768 px；默认列表、单页详情，保留返回入口；使用提供方的响应式能力 |

画布填满智能体标签的实际内容区。摘要、工具条和筛选悬浮在画布上方，缩放工具悬浮在左下角；选中代理后，对话和信息在可调整尺寸的悬浮详情容器中联动显示。打开详情不改变画布尺寸或视角。宽屏并列对话与信息，空间不足时切换为同一容器的标签页。容器使用提供方的面板与停靠接口，保留关闭及键盘访问。

## 5. S03 启动与 S04 主会话及团队树

![S03 主会话启动：使用 /agent-team](ux-design/screens/03-start.png)

*图 S03 · 启动团队 · 1440 × 900 px。保留宿主输入区，通过命令和自然语言启动任务。*

### 5.1 S03 启动

- 输入示例：`/agent-team 为知识库增加全文检索`。
- 命令建议展示“智能体团队”和简短说明；使用宿主已有命令补全，不新增大面积启动表单。
- 仅输入 `/agent-team` 而无需求时，提示“请描述希望团队完成的任务”，保留输入内容。
- 提交先出现普通 user prompt，并加载 agent-team skill。主会话 Agent 评估复杂度、生成启动参数，再调用 create；read 核实实际启动状态。团队创建记录位于用户需求之后。同一启动意图按相同参数重试时复用已有运行。

- 启动失败给出原因和“重试”；原始需求可恢复到输入区。重试对应同一提交意图，结果未知时先核实状态。
- 插件不可用时说明“dsh-flow 尚未启用”，提供回插件管理的入口，不悄悄当作普通提示词执行。
- 主会话后续指令沿用普通输入方式，不要求再次添加 `/agent-team` 才能答复当前团队的问题。

### 5.2 S04 顶栏按钮

- 按钮显示“智能体团队”及团队状态；数量可作为按钮内辅助信息，不增加相邻独立入口。
- 优先沿用官方浮层交互；图稿参考停留 200 ms 打开、移出触发区与浮层 250 ms 后关闭。移入浮层后必须保持可操作，不要求为参考时长重写提供方的悬浮逻辑。
- 单击按钮固定展开；再次单击、点击外部或按 Esc 关闭。触屏以点击打开。

- 团队未加载完成时使用结构骨架；没有子代理时显示总协调节点和“尚未派生子代理”。

### 5.3 S04 紧凑派生树

- 采用 `tree` 式缩进和连续层级连接线，根代理在首行；显示父子关系，不按状态排序打乱层次。
- 每行主信息为状态点 / 图标、代理会话标题；辅信息为状态文字、累计 Token 与运行时长。
- 名称与用量各占首行一端，状态与耗时各占次行一端；实际沿用提供方的截断与展开规则。完整文本必须可查看，不因截断丢失访问信息的入口。
- 悬浮在一行代理上时，状态右侧显示该代理的模型；移出即隐藏，不增加常驻信息密度。使用最近一次实际模型请求的记录，未请求时显示已确定的模型路由，未知时留空。列表和拓扑节点采用相同行为。
- 状态颜色遵循第 13 节；必须有状态文字，不能仅凭绿色、黄色、灰色判断。
- 名称、状态、用量与耗时作为一个按钮打开完整代理对话。右侧箭头独立，点击通过官方 sidebarRight.openResource 在侧边栏显示代理；左侧展开按钮仅展开 / 折叠后代。全部箭头复用官方 SVG，随展开状态翻转，遵守减少动效偏好。
- 拓扑采用居中树布局，圆形 emoji 头像与稳定的随机两字中文名字；卡片右上角以小字展示节点类型和状态。
- 悬浮时在状态右侧显示间隔符、厂商 Logo、模型与推理等级；厂商从模型名称推测，无法识别时使用通用图标。模型与推理等级优先来自实际请求回执。
- 选中和键盘焦点具有不同表现；当前查看代理可显示“正在查看”。
- 完成节点遵循显示偏好；折叠代理分支显示“已结束 3 个”，可临时展开。
- 底部“查看智能体”切换到 S05，并定位当前选中的代理（若有）。

### 7.2 对话阅读规则

- 消息角色、时间、正文与工具结果沿用宿主对话语义；仅呈现允许用户查看的内容。
- 创建子 Agent 的首条任务显示为普通 user prompt。后续 Agent 通信采用已确认的 A 方式：默认收起为单行摘要与简洁图标，点击原位展开类别、发送方 → 接收方、时间、关联任务与完整正文；保留长主题及结构化证据。类别为任务指令、进度反馈、结果反馈、审查意见、协作请求、阻塞与升级、资源协调、普通讨论；系统自动通知在详情中明确标注“系统”。系统摘要的计数与审核通过状态来自实际记录，不从模型正文推断。
- 流式消息追加在原消息中，不重复生成消息块；工具记录可以折叠，错误保留可读摘要。
- 首次打开遵循“对话自动跟随”设置；用户主动上滚后暂停跟随。
- 暂停跟随期间显示“有新消息 · 回到底部”，点击后滚到底部并恢复跟随。
- 用户本已处于底部时新消息可自然跟随；优先复用官方会话的跟随判定，图稿参考阈值为距底部 48 px，不要求自行实现同一套滚动逻辑。
- 向上加载历史保留当前首个可见消息及偏移，不把页面跳回顶部或底部。
- 切换代理时为每个代理保存本地阅读位置；首次查看无记录时按自动跟随偏好处理。
- 无消息显示“该智能体尚未产生可查看的对话”；不可访问显示原因，不冒充空会话。
- 底部固定提供“打开完整会话”；不出现输入框和发送按钮。

### 7.3 S07 完整原生会话

- 进入宿主主区域的代理 Session，复用原生对话、轨迹、历史加载、工具详情和输入框，不在“智能体”标签内另建完整会话渲染器。
- 顶栏展示代理名称、回收状态、所属主会话入口和团队下拉，可切换其他代理或返回团队。
- 未回收且团队未结束时保留原生输入框。通过原生 Session prompt/cancel 接口交给 Flow 执行所有者；冷会话的输入进入持久队列，活动轮次的输入进入其原生收件箱。角色权限、模型、预算和租约保持由团队管理。
- 回收或团队结束后，以历史记录说明替换输入框。服务器同样拒绝新消息；断线重试已接受的请求不会重复投递。
- 打开历史或切换轨迹不恢复普通 Agent、不产生模型请求；资源回收保留完整记录。
- 代理或运行链接失效时提供原因和主会话入口，不自动跳到其他代理。

## 13. 状态、计量与数据语义

### 13.1 代理执行状态与资源状态

| 执行状态 | 可读名称 | 视觉 | 说明 |
|---|---|---|---|
| `pending` | 待启动 | 中性点 + 文字 | 已创建，尚未开始执行 |
| `ready` | 待命 | 中性点 + 文字 | 已执行过轮次，目前可接受后续调度；明确协作依赖时使用对应等待状态 |
| `running` | 运行中 | 绿色点 + 文字 | 当前执行中 |
| `waiting_user` | 等待用户 | 黄色问询图标 + 文字 | 需要主会话中的用户答复 |
| `waiting_agent` | 等待其他智能体 | 黄色等待图标 + 文字 | 正在等待可标识的协作者或结果 |
| `blocked` | 受阻 | 黄色状态标识 + 文字 | 具体原因说明请求错误或执行停滞 |
| `paused` | 已暂停 | 黄色暂停图标 + 文字 | 上游明确报告暂停；界面无暂停 / 继续操作 |
| `completed` | 已完成 | 灰色完成图标 + 文字 | 本代理工作结束 |
| `cancelled` | 已取消 | 灰色停止图标 + 文字 | 本代理被上游取消 |
| `failed` | 失败 | 红色错误图标 + 文字 | 本代理执行失败 |
| 未识别 / 缺失 | 状态未知 | 中性问号 + 文字 | 保留原始可读说明，不自行映射为运行中 |

```mermaid
stateDiagram-v2
    [*] --> 待启动
    待启动 --> 运行中
    运行中 --> 等待用户
    运行中 --> 等待其他智能体
    运行中 --> 已暂停
    等待用户 --> 运行中
    等待其他智能体 --> 运行中
    已暂停 --> 运行中
    运行中 --> 已完成
    运行中 --> 失败
    运行中 --> 已取消
    待启动 --> 已取消
    等待用户 --> 已取消
    等待其他智能体 --> 失败
```

图为常见状态转移说明，并非禁止其他由权威数据明确提供的转移；前端不得依此自行推进状态。`已回收` 是独立资源属性，可叠加在终态上，不作为执行状态替代“已完成 / 失败 / 已取消”。

### 13.2 三类计量独立呈现

| 类别 | 定义 | 显示规则 |
|---|---|---|
| 累计 Token | 已发生的累计 Token 用量 | 可分输入 / 输出；上下文压缩不使累计用量减少 |
| 预算 | 提供方报告的额度信息 | 原样表达种类、单位、作用域、共享 / 独立属性；只读 |
| 上下文 | 当前会话已用上下文与可用上限 | 与累计 Token 分开；可因压缩而下降 |

- “累计 Token”必须指明是当前代理自身，还是包含后代；默认节点展示当前代理自身，团队汇总只去重计入一次。
- 如果数据只提供包含后代的统计，明确标注“含子代理”，不得将这些值逐层相加得到团队总量。
- 预算以独立条目展示名称、总额度 / 已用 / 剩余（若提供）、单位、作用域及共享标记；没有提供的字段显示“尚未提供”。
- 共享预算显示“与团队共享”，并指明团队；独立预算显示“当前代理独立额度”。不能仅凭所在面板推断作用域。
- 不同单位预算不相加、不统一转成百分比，也不从 Token 消耗自行推算金钱或时长。
- 不配置预算阈值，不自行预测耗尽时间；提供方明确报告预算相关等待或错误时，按原始原因显示。
- 上下文同时具备已用和上限且单位一致时，才展示占用百分比；仅有一项时显示该项与缺失说明。
- 上下文压缩事件可显示“上下文已压缩”及时间；不据此声称任务结果或历史消息被删除。
- 未知用量显示 `—`；明确的零显示 `0`；估算值加“约”，不得混用三者。
- 简写建议保留一位小数并去除末尾零，如 `12.8k`；精确值使用千位分隔，如 `12,840`。
- 运行时长与等待时长分别由明确起止时间计算；结束后冻结时长，断连时标注时间数据的有效性。

### 13.3 开发所需的概念契约

下表描述界面需要的信息，不指定现成 API、存储格式或生产接口；开发阶段应与数据提供方确认映射和缺失策略。

| 对象 | 必需信息 | 可选信息 / 缺失策略 |
|---|---|---|
| 团队运行 | 稳定运行 ID、主会话 ID、状态、创建时间、数据版本 | 结束时间、结果摘要、累计用量；缺失不伪造 |
| 代理 | 稳定代理 ID、运行 ID、父代理 ID、名称、状态 | 职责、会话 ID、状态原因、回收属性、起止时间 |
| 用量 | 所属对象、数值、单位、统计范围、更新时间 | 输入 / 输出明细、是否估算；范围未知则不参与汇总 |
| 预算条目 | 名称 / 种类、单位、作用域、共享 / 独立属性 | 总额、已用、剩余及提供方说明；不要求每种均存在 |
| 上下文 | 所属会话、已用或上限、单位、更新时间 | 压缩事件；无上限不展示比例 |
| 会话消息 | 稳定消息 ID、代理 / 会话归属、角色、时间、内容、可见性 | 流式阶段、工具记录；缺失显示局部状态 |
| 通信 | 稳定通信 ID、运行 ID、发送方、接收方、时间 | 摘要、正文、传递状态；传递状态不推断执行状态 |
| 实时更新 | 对象标识、可排序版本 / 序号、事件时间 | 快照基准和恢复游标；无法增量恢复时重新获取快照 |

## 14. 实时一致性与稳定布局

- 顶栏树、拓扑、列表、对话、信息面板必须读取同一运行和同一代理标识体系；名称不是主键。
- 同一对象较旧版本的更新不得覆盖新版本；重连或重试后的重复事件按稳定标识去重。
- 状态、通信、用量与资源回收是独立信息：收到一条消息不代表恢复运行，回收不代表成功完成。
- 子代理先于父代理到达时暂存或显示“正在补全关系”；不把它错误挂到根节点。
- 代理标题更新不改变节点身份、选择、消息归属或历史链接。
- 数据更新与视觉动画分离；动画可以跳过，但不能丢失最终节点、状态或通信记录。
- 每批更新后同步完成关联视图刷新，避免同一代理同时显示不同终态；加载中的部分标注更新时间。
- 断连恢复先合并权威快照，再处理其后的更新；不能重新播放全部历史派生和通信动画。
- 已结束对象收到明确的数据修正时可更新，并标注更新时间；不要通过前端计数单调性掩盖真实修正。
- 通用动画优先使用提供方的组件与动效参数。图稿参考新代理出现 180–220 ms、节点状态过渡 150 ms、抽屉打开 / 关闭 200 ms，不要求覆盖官方时序。
- 专属通信高亮参考持续 600–900 ms；同一连线频繁更新合并计数，避免无限动画队列。
- 回收动画使用短暂减弱和标签变化，随后稳定保留历史节点；不做节点消失后无法访问的效果。
- 减少动态效果时取消位移、流动与脉冲，直接更新状态，并保留静态高亮提示。
- 用户查看区域尽量稳定；新增节点优先分配局部空间。必要的大范围重排保留当前选中节点屏幕锚点。
- 搜索、过滤和折叠引起的主动布局变化可以重新组织显示，但保留清晰的当前条件与恢复入口。

## 15. 通用交互、无障碍与文案

### 15.1 键盘与辅助技术

- 所有按钮、标签、展开控件、列表项和详情入口均可由键盘操作；优先使用提供方的可见焦点样式，图稿参考为 2 px 蓝色描边、偏移 2 px。参考尺寸可调整，但焦点可见及可辨识要求不变。
- 标签使用标准标签页语义；方向键切换标签焦点，Enter / Space 激活；内容区具有对应名称。
- 图提供等价列表，读屏用户无需理解空间坐标即可获得层级、状态、用量与导航。
- 树按可见层级顺序进行键盘遍历；左右键折叠 / 展开，上下键移动，Enter 打开或选中。
- 浮层打开后管理焦点；Esc 关闭最上层，关闭后回到触发控件；非模态面板不困住整个应用焦点。
- 状态不得仅用颜色表达；辅助技术名称包含代理名称和状态，通信按钮包含发送方与接收方。
- 实时消息只播报必要变化摘要，避免逐 Token 播报；等待用户、失败和连接中断可使用温和提示。
- 普通文字与背景对比度至少 4.5:1，大字和关键控件边界至少 3:1；低对比分割线不单独承载含义。
- 长中文、200% 缩放和系统大字体下不截断核心操作；详情内容允许换行，ID 可折行或复制。

### 15.2 标准文案

| 场景 | 文案 |
|---|---|
| 观察视图 | 不显示重复只读说明；主对话入口与输入策略表达操作边界。 |
| 等待用户 | 需要你确认：结果摘要需要包含上下文吗？ |
| 等待协作者 | 正在等待“检索实现”的结果。 |
| 数据断连 | 连接中断，显示的是上次数据。最后更新：{时间}。 |
| 指标未知 | 尚未上报 |
| 回收说明 | 运行资源已释放，历史记录仍可查看。 |
| 设置保存成功 | 显示设置已保存。 |
| 设置保存失败 | 未能保存显示设置，你的更改已保留。 |
| 空对话 | 该智能体尚未产生可查看的对话。 |
| 主会话导航 | 返回主会话 / 前往主会话答复 |

文案不使用“已读”代替已送达，不使用“完成”代替已回收，不把所有黄色状态统称为“挂起”。图中的简化文案与本节语义必须一致。

### 17.2 P0 范围控制

- 不实现代理控制台、直接通信输入、模型选择、权限编辑、工作区管理或新的任务调度界面。
- 不实现预算编辑、充值、阈值告警规则、消耗预测、费用换算及自动调度建议。
- 不把动画效果、任意自由排布或三维关系图作为 P0 必需；先交付稳定的层次图和等价列表。
- UI 接入先完成 D0，优先复用官方实现和实际提供方的公开接口；数据接入按第 13 节确认映射。未经核实不宣称接口已存在或已经兼容。
- 预览是离线设计场景集，支持关键导航、节点选择、图 / 列表、详情、主题和设置草稿演示；不接后台，不模拟真实流式消息、乱序事件、运行状态转移、千节点性能或全部无障碍行为。上述生产要求按验收表实施，不能由预览通过替代。
- 实际开发交付应包含各屏幕状态、边界数据、无障碍检查及验收记录，不能仅凭静态截图认定完成。

### 17.3 本规格与图稿的使用方式

图稿说明信息层级、相对布局和可见交互意图；正文规定行为、语义与边界。图中所有像素尺寸、比例、色值和样式均为参考，具体呈现服从实际 UI 提供方的公开接口与官方交互惯例。实现与示意图存在尺寸或外观差异，只要保留业务语义、可读性及导航关系，不视为偏离本规格。若图稿出现超出只读或预算展示范围的操作，应修正图稿，不将其解释为隐含的新功能。

所有 UI/UX 冲突按 1.5 处理：当前正文是唯一设计依据，配套图稿和预览必须与正文同步；旧页面、旧模式、旧文档及现有代码不能推翻本规格，也不构成保留旧交互的理由。

离线预览为了独立展示而绘制了宿主外壳，它不是生产 UI 的创建方案。不得将其侧栏、顶栏、标签栏、面板或会话 DOM / CSS 直接搬入插件作为替代宿主接口的实现。生产验收必须在实际 dsh 与相关 UI 插件环境中完成；图稿比对不能替代接口接入和样式适配验证。

设计资源位于 `docs/plans/ux-design/`：`index.html` 是交互预览入口，`app.js` 和 `styles.css` 是设计源，`screens/` 保存 14 张主界面图及浅色、手机详情补图；`render.mjs` 可重新生成全部图片。后续调整应同步更新规格、预览和对应截图，确保三者表达同一设计。

图稿再生成：在仓库根目录执行 `node docs/plans/ux-design/render.mjs`。脚本使用工作区现有 Playwright 与本机 Chrome；不会修改应用源码或连接真实任务。`screens/render-report.json` 记录实际图片尺寸和浏览器错误；交互检查范围见 `verify.mjs`。

## 安装验证

- 当前插件为 `dsh-flow@0.1.0`，宿主为 `@deepseek-ai/dsh@0.1.7-rc.2`。
- 通过 `pnpm pack` 生成本地安装包，打包前构建成功。
- 在独立临时 DSH 数据目录中，使用精确版本的 `npx` 命令实际执行插件安装和列表查询，确认安装的是 `0.1.0`。
- Node.js 前提已核对 DSH 发布包的入口条件：22.19.0 及以上的 22.x，或 24.2.0 及以上版本；24.0.x/24.1.x 缺少 `import.meta.main`，可能静默退出。
- 使用公开启动配置执行 `web --patch ... --dump-config`：确认集群插件仅出现一次，模型路由读取宿主默认选择，宿主压缩已启用，工作目录与权限配置正确。
- 公共 npm 上的同名 `0.0.1` 为旧工作流插件；文档未使用按包名安装的错误路径。

## 真实运行与截图

使用用户指定的 OpenAI 兼容模型服务。服务地址及凭据不进入公开文档或图片。

- 模型：`qwen3.8-flash-next-unsloth-ud-iq4_xs`。
- 初次连接发生流式响应超时，尚未创建集群。演示进程改为内网直连并增加等待时间后，能调用模型。
- 关闭推理时，编排智能体连续 7 次查询不存在的黑板条目，未派发任务；该轮已通过正常面板取消。
- 开启推理后重新运行，任务完成派发，独立计划审计通过；但模型申请了本题不需要的 `fs_read`，执行智能体因 `read/glob/grep` 不可用而在模型调用前阻塞。该轮已通过正常面板取消。
- 纯计算示例的启动配置明确将默认能力设为空，提示词也明确不授予文件或命令执行能力；配置默认时限设为 30 分钟，为模型规划与独立复核预留时间。随后使用干净实例重新执行；会话显式传入了单次预算（60,000 Token、40 次模型请求、30 次工具调用、15 分钟），此轮实际以该预算为准。
- 用户随后要求停止实跑，改为用生成的界面图表达预期交互。已通过正常取消操作停止本轮集群，结束服务并删除临时凭据；本轮没有形成执行计算和验收成功的实跑证据。

演示启动遇到执行环境的原生文件监听限制。相同只读监听探针在普通沙箱中返回 `EMFILE`，在允许原生文件监听的环境中正常就绪；相应重启后，加载器确认所有 159 个条目均已激活且无待处理任务。未禁用宿主热更新、认证或启动审查，也未修改产品代码或任务状态来制造进度。

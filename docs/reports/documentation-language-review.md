# 文档中文校对记录

校对日期：2026-10-06。

范围：`docs/design/` 下的 21 个文档页面，以及站点导航和 15 张 Mermaid 图的显示文字。校对目标是统一中文术语、修正不自然的句式，同时保留接口、配置和系统行为的准确含义。

## 统一术语

以下五项经用户确认：

| 原名称 | 正文用语 |
|---|---|
| Orchestrator | 编排智能体 |
| Allocator | 资源分配智能体 |
| Auditor | 审计智能体 |
| Worker | 执行智能体 |
| Transaction | 任务单元 |

角色英文名称集中放在角色对照表中，便于查阅源码。数据库事务仍称“事务”，与任务单元明确区分。代码标识符、API 名称、字段、枚举、命令和文件路径保持原样。

其他术语按语境处理：执行轮次不同于一次模型请求；模型上下文不同于宿主上下文对象；权限作用域不同于预算账户。“升级”在问题处理流程中写为“提请上级处理”，“收敛”按具体含义写成结果汇总、交付或收尾。保留 API、Token 等必要术语，以及 DeepSeek Harness、VitePress、Mermaid 等产品或技术名称。

## 审查过程

第一轮按章节逐段改写，不仅替换词语，还检查主语、动作、责任方和生效条件。

第二轮交换章节，由未参与对应页面改写的审阅者独立通读，并与修改前版本对照。分工如下：

| 页面范围 | 首轮作者 | 独立审阅者 | 最终结论 |
|---|---|---|---|
| 智能体分类、层次结构、任务派发、通信，共 4 页 | 概念组 | 开发组 | 通过 |
| 快速上手、两类配置参数、兼容性，共 4 页 | 配置组 | 概念组 | 通过 |
| API、动作索引、代码结构和 8 个组件，共 11 页 | 开发组 | 配置组 | 通过 |
| 欢迎、开发文档首页，共 2 页 | 主编辑 | 概念组；执行完成语义另由开发组核对 | 通过 |

第三轮由提出问题的审阅者核对修订结果。存在未解决问题时维持“不通过”，修正并再次核实后才改为“通过”。文字审查之后，对图形另行进行浏览器检查和逐图目视检查。

## 独立审查发现并修正的问题

| 问题 | 修正结果 |
|---|---|
| 将替换、缩容和迁移一概写成转移任务归属 | 改为核对任务责任、执行分配与预算归属是否一致，不暗示每次操作都改变任务归属 |
| 将整棵管理树的控制范围写成单个管理域 | 改为查询各自操作范围内的完整数据，明确不能使用界面中的一页数据代替完整范围 |
| 工具权限说明未区分继承工具和当前作用域中的工具 | 分别说明继承工具的可见性限制，以及全部工具的执行权限检查 |
| 将候选结果的暂存与正式发布混写 | 明确可以先暂存；宿主执行轮次正常结束、租约与记账检查通过后才能正式发布 |
| “执行期间替换执行者”容易被理解为可直接替换仍在运行的智能体 | 明确先到达安全点，并结束旧执行轮次和租约 |
| 状态图把本次执行完成写成宿主的一轮执行结束 | 使用“本次执行完成”，并保留逻辑生命周期与当前实现的区别 |
| “运行中的身份”“计量预算”等搭配不当 | 根据实际对象改为运行中的智能体、计量资源用量等表述 |
| 中文标签出现孤字断行，状态图边标签重叠，宽时序图字号偏小 | 调整标签断行和边说明；时序图默认按原尺寸显示并支持横向滚动，也可切换为适应宽度 |

另外修复了兼容性表格中的 Node.js 版本范围显示：对 Markdown 竖线进行转义，确保 `^22.19.0 || >=24.0.0` 完整呈现，版本约束未改变。

## 校验范围与结果

- 25 个命令或配置示例中，24 个逐字未变；1 个 JSON 示例只将说明性占位文字 `<本域 Agent ID>` 改为 `<本管理域的智能体 ID>`，字段和值的类型未变。
- 3 个纯文本流程或目录示例只修改说明文字，目录路径和配置字段未变。
- 15 张图的节点标识、连接关系和时序参与者顺序保持不变；状态图使用中文显示名，原枚举值仍可对照。
- 动作索引的 54 行、53 个唯一动作及参数保持不变。
- 文档构建通过；21 页均返回正常状态，站内链接和锚点检查通过，本地 Markdown 下载内容与源文件一致。
- 中文术语搜索、复制页面、深浅色切换、手机端导航和图形横向滚动检查通过。
- 图形排版调整后的自动检查及独立目视复核均通过：中文标签无裁切或重叠；时序图默认原尺寸可读，支持横向滚动与适应宽度；切换主题保留尺寸选择，切换页面按新图类型恢复默认显示。

本轮仅修改文档及文档站的展示代码，未修改智能体运行时，也未改变模型调用、配置默认值或命令参数。浏览器检查只访问本地文档站，没有启动真实模型任务。

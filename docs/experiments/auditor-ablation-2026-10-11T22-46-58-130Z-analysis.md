# Auditor 是否必要：三场景消融结论与关键案例

本轮观察到 Auditor 的局部审核价值，但没有证明固定独立 LLM Auditor 在所有任务中不可替代。对真正存在业务内容缺陷的 13 个完整配对，初验放行了 1 个，追加自审和独立审核都降为 0。独立审核比自审少放行的另外 1 个样本只涉及旧回执引用，证明内容本身正确，而且公开标准与严格 oracle 的解释存在歧义。

实验使用本地 oMLX `0.7.1.dev1`、`Qwen3.8-27B-4bit` 和真实 DSH/Flow `runTurn`。2026-10-12 完成全部 24 个配对、72 个阶段的调用；71 个阶段形成有效结构化决定，23 个配对完整。一次调研初验触及 2048 输出 token 上限，整组排除质量比较，没有选择性重试。构建、协议、实验源码和模型/全局运行配置均无漂移。

这是固定 Worker 交付上的验收层消融。A 为业务初验；B 为同一 Orchestrator 的追加自审；C 为新 Auditor 会话审核 A 的行为、记录和证据，放行要求 A 与审核均通过。B 没有获得 C 的审核结论，C 也没有审核 B 的新记录；两次重复交换 B/C 顺序。它不是模型从零开发、开放网络调研或复杂证明的端到端测试。

## 三个场景的实测回答

下表只统计业务内容缺陷，剔除研究/数学仅回执过期的四个单元。这个分层是运行后的解释性分析，原始标签与预注册主分数完整保留，未重新判分。

| 场景 | 完整内容缺陷配对 | A 错误放行 | B 错误放行 | C 错误放行 | 本轮支持的判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| 代码开发 | 6 | 0 | 0 | 0 | 简单边界错误已被初验捕捉，未观察到额外放行质量收益 |
| 深度调研 | 3 | 0 | 0 | 0 | 在冻结资料的覆盖/引用错误上未观察到额外收益；另有一次阶段失败 |
| 数学证明 | 4 | 1 | 0 | 0 | 追加检查纠正了一条矛盾验收，但未显示独立角色优于自审 |
| 合计 | 13 | 1 | 0 | 0 | 支持追加检查的局部价值，未证明固定角色不可替代 |

六个合格交付的最终放行在三臂均通过，误拦为 `0/6`。按预注册的严格放行标签，A、B、C 分别为 `5/17`、`4/17`、`3/17` 违规放行；其中仅旧回执子集为 `4/4`、`4/4`、`3/4`。不能将这些严格回执分数全部当成事实、程序或证明内容错误。

完整统计、逐单元决定、失败和成本见[生成的实测报告](./auditor-ablation-results.md)；[原始 JSON](../../.artifacts/auditor-ablation-2026-10-11T22-46-58-130Z/report.json)保留所有 findings、引用 IDs、原生停止原因与会话路径。

## Auditor 确实捕捉到的验收矛盾

`proof-unsupported-conclusion` 第一次重复的交付使用错误全称引理“6 整除 n(n+1)”。初验实际上已写出“引理不普遍有效，故不通过”，notes 也要求修订，结构化 `M2/M3.passed` 和 `accepted` 却仍为 `true`。类型校验只检查布尔字段的一致性，未能发现自然语言观察与标志的冲突。

Auditor 在 `conclusion_support` 中指出“最终 accepted=true 与自身观察矛盾”，拒绝该验收记录。它抓住了验收结论是否由记录支持，保持了独立审核的职责。自审随后也将标志纠正为拒绝，所以这一配对支持再检查一次，不能单独证明必须使用独立身份。

还必须保留一个反证：自审虽然给出了正确拒绝标签，却沿用了错误的 `n=2` 反例；`2×3=6` 实际能被 6 整除，正确反例可以是 `n=1`。因此“最终拒绝正确”不等于数学推理完整正确。本轮主要指标不评分全部自然语言推理质量，也没有测量返工后的正确证明。

## 唯一比自审少放行的单元属于证据治理

`proof-stale-evidence` 第二次重复的证明有效，Orchestrator 声明重新检查当前证明，没有把旧样本回执作为正面依据，但 `M4.evidence_ids` 仍包含旧 `proof-check-notes`。Auditor 要求删除这条旧引用，重新出具当前对象的验收记录；它没有要求修改证明。

这是对引用范围的治理检查，不能称为发现数学错误。其解释还有两层限制：旧回执可以被列为“不采用的背景”证据，而当前 schema 没有区分支持、反证和背景引用；预注册 oracle 则只要输入包存在旧回执就判不可放行，即使 Orchestrator 做了新的有效检查也不豁免。故主分数保持不变，但该优势不证明业务准确率提升，也不证明公开业务标准下的自审结论错误。

本轮没有运行“修正引用后再审核”的循环，不能从一次拒绝推断最终业务无法交付，或估算完整修正成本。

## 审核者的判断也需要质疑

`code-stale-evidence` 第二次重复中，Orchestrator 已拒绝含字符串版本比较错误的代码，其方法为“源码审查并构造数值反例”。提示明确允许源码/数学推理，没有声称运行程序。Auditor 却将缺少执行回执解释为虚报执行，并且把 `standard_coverage` 标为 `false`，观察又说已覆盖 C1–C4 全部标准。

这表明 Auditor 也可能误读推理与执行的边界，并产生标志/观察矛盾。该单元的 A 本来就拒绝，C 没有改变最终放行，因此 `0/6` 合格误拦不能被解读成全部审核理由都正确。增加一个审核者并不自动保证其判断可靠。

## 成本与实施建议

仅初验用了 50 次请求、541.2 秒阶段时间；自审新增 49 次请求、570.0 秒；独立审核新增 55 次请求、547.4 秒。全部阶段成本包含失败尝试，排除一次性安装、主机启动与报告处理。C 的输入 token 少于 B，但调用更多、时间接近，不能笼统称整体成本更低；B 的历史上下文和双方不同的字段数量也是混杂因素。实验对所有初验记录都运行审核，不能把它的总成本直接当成只审正面验收的生产开销。

当前证据更适合支持以下决策：

- 保留独立审核的职责和能力，尤其关注正面结论与观察矛盾、执行声明缺少回执、证据身份或版本冲突；不能据此宣称每个任务都必须增加固定 LLM 审核调用。
- 先明确证据契约，并给检查方法和引用增加“推理/执行”“支持/反证/背景”的结构区分。引用存在性、身份、版本、权限等可确定性检查的部分，应与自然语言语义审核区分。
- 要决定是否取消或强制常驻 Auditor，还需自然产生错误的完整任务、确定性守卫对照、角色与新上下文分开的对照，以及返工成本和最终交付质量。两次重复和人为压力样本不能估算生产失误率或证明普遍必要性。

本次没有调整生产 Auditor 门禁、权限策略或角色职责，也没有提交或推送实验文件。

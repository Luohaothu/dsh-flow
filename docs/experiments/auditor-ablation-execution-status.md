## 已就绪的实验

每个场景包括一份合格交付和三份缺陷交付，重复两次，共 24 个配对单元、72 个原生阶段。A 为 Orchestrator 初验；B 为同会话追加自审；C 为独立 Auditor 审核 A 的验收记录，放行仍要求 A 通过。具体预算、冻结规则、归因限制和判定标准见[执行前协议](./auditor-ablation-protocol.md)。

Auditor 保持独立审核验收行为和证据的职责。实验使用真实原生 `runTurn` 和当前角色提示，但通过隔离的 `experiment_*` 工具收集决定，不修改或绕过生产验收门禁。固定 Worker 交付用于测试验收层；本轮不测量从零开发、开放网络调研、复杂证明或返工后的最终交付。

## 校验与继续运行

构建、类型检查、六项实验单元校验、来源引用证据及原生记录复核通过。单元校验包括真实代码边界执行、缺陷夹具分类、错误数学证书、缺失/无关引用、原生中止排除和 Auditor 不能推翻业务拒绝。源码和协议漂移、模型 recipe 漂移、缺失决定及 native 未完成都会使该轮或该配对不适用于质量结论。

新的独立复现轮应先确认 oMLX 的 active/waiting 均为 0，再执行：

```bash
pnpm experiment:auditor --pilot
# 三阶段均完成、complete_pairs=1；入口会检查源码、协议和模型 recipe 一致性
pnpm experiment:auditor
pnpm experiment:auditor:report .artifacts/<run-id>/report.json
```

正式入口强制要求同版本、同模型 recipe 的完整先导。本轮报告同时展示缺陷错误放行、合格误拦、A 已通过子集、阶段错误与成本；若 C 不优于等预算自审，只能支持追加检查，不能宣称 Auditor 不可替代。

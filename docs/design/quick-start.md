# 快速上手

本教程带你在 DeepSeek Harness（dsh）中安装 dsh-flow，再用**集群模式**核对一份活动预算。你只需提交目标，集群负责拆分任务、执行计算和独立复核；完成后，你可以查看结果及其验收记录。

## 安装前的准备

你需要：

- Node.js `22.19.0` 及以上的 22.x 版本，或 Node.js `24.2.0` 及以上版本。
- pnpm，供 dsh 安装插件时使用。可运行 `pnpm --version` 检查；尚未安装时，执行 `npm install --global pnpm@12.9.1`。
- 可调用工具的模型服务，以及该服务需要的地址、模型名称和密钥。
- 当前集群版插件的安装包 `dsh-flow-0.1.0.tgz`。

本教程使用 **dsh `0.1.7-rc.2`**，这是当前插件声明兼容的 dsh 版本。其他版本的兼容情况见 [dsh 兼容性](/development/compatibility)。

::: info 获取插件安装包
当前集群版通过 `.tgz` 安装包安装，请向插件提供方取得 `dsh-flow-0.1.0.tgz`。公共 npm 上的同名 `dsh-flow@0.0.1` 是另一版工作流插件，不能用于本教程。需要自行构建安装包时，见[开发环境搭建](/development/setup#_3-安装到独立调试实例)。
:::

## 安装与启动

### 1. 启动 dsh，配置模型

在终端运行：

```bash
npx @deepseek-ai/dsh@0.1.7-rc.2 --version
npx @deepseek-ai/dsh@0.1.7-rc.2 web
```

版本检查应输出 `0.1.7-rc.2`。若命令没有输出就退出，请先检查 Node.js 版本；dsh 的命令行入口使用了 [Node.js 的 `import.meta.main`](https://nodejs.org/download/release/v26.8.2/docs/api/esm.html#importmetamain)，不支持 24.0.x 和 24.1.x。

打开终端给出的网页地址，在 **设置 → 模型** 中配置模型服务。内置提供方通常只需填写密钥；使用自定义 API 时，还需要填写服务地址、接口类型和模型名称。保存后回到会话，在模型选择器中选中要使用的模型。详细配置方法见 [dsh 官方模型说明](https://deepseek-harness.github.io/deepseek-harness/guide/providers)。

插件启动时会读取 dsh 的默认模型。因此，请先配置并选好模型，再安装插件、重新启动 dsh。之后需要更换集群使用的模型时，也应重新启动；在输入框旁切换会话模型，不会改变已经运行的集群。

### 2. 安装插件

在运行 dsh 的终端按 `Ctrl+C` 停止服务。将下面的安装包路径替换为实际路径，再执行：

```bash
npx @deepseek-ai/dsh@0.1.7-rc.2 plugin --profile web add /绝对路径/dsh-flow-0.1.0.tgz
npx @deepseek-ai/dsh@0.1.7-rc.2 plugin --profile web list dsh-flow --depth 0
```

第二条命令的输出应包含 `dsh-flow@0.1.0`。插件安装后会自动加入当前 `web` 配置方案，下次启动时加载。

### 3. 准备工作目录并重新启动

先创建并进入用于练习的目录：

```bash
mkdir -p flow-demo
cd flow-demo
```

下载[集群启动配置](/downloads/cluster.patch.yml)，将文件保存为当前目录中的 `cluster.patch.yml`，再启动 dsh：

```bash
npx @deepseek-ai/dsh@0.1.7-rc.2 web --patch ./cluster.patch.yml
```

这份配置沿用你刚选好的模型，将当前目录用作集群工作目录，把运行记录保存到 `.dsh-flow`，并启用长任务需要的上下文压缩。本例只做计算，因此默认不授予文件或命令执行能力；处理文件类任务时，再按[高级使用](/advanced#选择工作目录和权限)配置所需能力。

启动配置的默认运行时限为 30 分钟，覆盖规划、计算和独立复核。会话创建集群时如果另外指定了本次预算，则以本次预算为准，可在面板的 **resources** 页查看。实际耗时取决于模型服务。

集群在后台执行，不能等待用户逐次审批。这份配置把当前配置方案中新会话的默认权限设为“允许工作区写入、不请求审批”；超出权限且需要审批的操作会被直接拒绝。该默认值也影响普通会话，使用前请确认工作目录。权限与能力的区别见[高级使用](/advanced#选择工作目录和权限)。

以后继续使用这个实例时，在同一目录用同一条启动命令运行即可。保留 `.dsh-flow` 和 dsh 的数据目录，才能继续查看运行记录。

## 完成第一次集群对话

这次练习要核对三项活动开支，判断是否超出总预算。从提出目标到查看分工、验收结果，再回到对话获取总结，你可以完整体验一次集群协作。示例模型为 **Qwen**，图片可点击放大。

### 第一步：选择工作区与集群模式

在 dsh 中新建会话，选择刚才创建的 `flow-demo` 工作区。在输入框旁打开模式菜单，选择 **集群模式**，并确认模型选择器中的模型。本例使用 **Qwen**。

[![在 flow-demo 工作区新建会话，通过输入框旁的模式菜单选择集群模式](/images/quick-start/01-cluster-mode.png)](/images/quick-start/01-cluster-mode.png)

集群模式会将目标交给一组分工协作的智能体。你可以像平常对话一样描述需求，无需预先安排每个智能体的工作。

### 第二步：提交预算核对目标

把下面的内容粘贴到输入框：

```text
帮我核对这次活动的预算：场地费 1500 元、物料费 680 元、茶歇费 420 元，
总预算 3000 元。请安排计算和独立复核，告诉我总支出、剩余预算以及是否超预算。
完成后用一句话总结。
```

[![发送前，在会话输入框中填写活动预算核对要求](/images/quick-start/02-submit-objective.png)](/images/quick-start/02-submit-objective.png)

确认金额和要求后，点击发送。会话会创建集群并返回集群 ID，后续可以用这个 ID 在面板中找到本次任务。示例会话名为 **活动预算核对**。

### 第三步：查看智能体分工

点击左侧 **Cluster**，进入集群面板。在 **Clusters** 列表中选择本次任务对应的集群，然后打开 **tree** 页，点击 **Load root** 加载根节点，再点击节点展开下级结构。

[![在 Cluster 面板的 tree 页展开 management 管理节点和下级 worker 执行节点](/images/quick-start/03-cluster-tree.png)](/images/quick-start/03-cluster-tree.png)

树中的 `management` 表示管理节点，`worker` 表示执行节点。一个管理节点由三类角色共同负责：

- **编排智能体**安排核算任务，并按要求验收结果。
- **资源分配智能体**选择执行者，为任务分配所需资源。
- **审计智能体**独立复核计划和验收结论。

具体计算由执行节点中的**执行智能体**完成。树中的节点展示组织关系，四类角色的职责决定了谁规划、谁分配、谁执行、谁复核。

面板提供六个页签，可以按需要切换：**tree** 查看管理树，**transactions** 查看任务单元，**communication** 查看通信记录，**context** 查看上下文用量，**health** 查看编排履职情况，**resources** 查看资源用量。

### 第四步：查看结果与验收记录

打开 **transactions** 页，选择核算任务。示例中的任务单元为“预算核算”，核对结果应为：

| 核对项 | 结果 |
| --- | --- |
| 总支出 | **2600 元** |
| 剩余预算 | **400 元** |
| 是否超预算 | **未超预算** |

[![在 transactions 页查看预算核算的结果、业务验收和独立审查记录](/images/quick-start/04-transaction-result.png)](/images/quick-start/04-transaction-result.png)

详情中的 **result** 展示提交结果，**validation** 展示业务验收记录，**audit** 条目展示审查结论和证据。执行智能体提交结果后，编排智能体检查它是否满足要求，审计智能体独立复核。业务验收与独立复核均通过，任务单元才能被正式接受。

::: tip 如何判断任务单元已通过验收
详情中的状态为 `ACCEPTED`，表示该任务单元已被正式接受。它说明这一项工作通过验收，整个集群还需要完成汇总和收尾。
:::

### 第五步：回到对话并保存报告

集群状态变为 `COMPLETED` 后，点击左侧的 **活动预算核对**，回到原会话查看总结。核对结论可以概括为：

> 本次活动总支出 2600 元，剩余预算 400 元，未超出 3000 元的总预算。

[![从左侧打开活动预算核对会话，查看总支出、剩余预算和是否超预算的总结](/images/quick-start/05-completed.png)](/images/quick-start/05-completed.png)

需要保存报告时，点击左侧 **Cluster** 返回集群面板，选中本次集群，再点击面板右上角的 **Download report**。报告包含运行概览和验收、审计统计摘要；详细结果与审查记录可以在 **transactions** 页查看。

::: tip 区分单项验收与整体完成
`ACCEPTED` 表示一个任务单元已被正式接受，`COMPLETED` 表示整个集群已完成交付和收尾。确认集群状态后，再对照最初要求检查结果。
:::

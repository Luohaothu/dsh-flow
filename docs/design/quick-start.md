# 快速开始

## 准备宿主

使用 DSH `0.2.0-rc.2` 的正常 web profile，安装 `dsh-flow` 并加载插件。Provider 与默认模型通过宿主设置保存到 profile；团队沿用标准 preset 和实际权限。

配置示例：

```yaml
- id: dsh-flow
  config:
    dataDir: .dsh-flow-native
    workspace: .
    maxConcurrentAgents: 4
```

使用独立的新数据目录。旧契约数据库会被明确拒绝，原数据保持完整。

## 开始协作

从主会话使用 `/agent-team` 或 `agent_team_create`，提供清楚的目标。根任务由已有的主 Agent 持有；创建团队不会再启动一个执行相同目标的后台成员。需要独立工作时，通过 `flow_task` 创建子任务与标准成员。

只委派能够独立推进的业务部分，写清各自产物的负责人。主 Agent 继续互补工作，避免与成员重复执行同一完整目标或同时改写同一文件。委派者亲自使用原生工具检查已有交付，按原完成条件接受；不为凑人数、形式上的独立评审或更多来源另开成员。真正需要继续分解的业务仍可使用相同接口递归委派。

取得委派身份后，主 Agent 可以完成自己的工作并自然结束当前回合，等待真实结果通知。不要另外启动 shell 循环等待成员文件。收到交付后实际检查，再接受对应结果；完整交付由主 Agent 提交根结果并确认完成。

任务执行者提交具体成果。请求者用正常 read、bash、web 或配置的 MCP 工具检查，再接受或退回当前结果。阶段成果和受阻说明不会自动成为成功。

团队界面展示协作事实并连接原生对话。取消当前活动使用原生取消；团队暂停停止新投递，同时使用原生 cancel 停止并排空当前活动；恢复通过正常输入继续。查看历史会话不会恢复任务或唤醒模型。

# 作业与交付

作业是一次需要状态追踪和结构化结果的正式任务委派。派发者提供任务背景、需求、验收标准、材料和结果 schema，运行时记录作业状态，并在提交时检查格式和保存结果。

状态询问、讨论、澄清和轻量的信息共享通常使用普通消息。只要希望对方按要求返回内容，请求中也应说明返回格式和验收标准；这类消息由 Agent 自行遵循约定。

## 描述一份完整任务

`AssignmentSpec` 描述任务本身。schema 随本次任务制定，同一个 Agent 接收不同作业时可以使用不同的结果格式。

| 字段 | 作用 |
| --- | --- |
| `name / type` | 标识任务名称与业务类型。 |
| `background` | 说明任务缘由和相关背景。 |
| `requirements` | 列出本次需要完成的工作。 |
| `acceptanceCriteria` | 说明派发者判断内容质量的依据。 |
| `resultSchema` | 规定提交结果必须符合的结构。 |
| `materials` | 可选的材料引用，包含输入的实际来源与读取信息。 |
| `resumesAssignmentId` | 可选的历史来源，用于显式继续先前工作。 |

以下任务要求返回核查摘要及问题证据：

```json
{
  "name": "发布说明核查",
  "type": "release-review",
  "background": "项目准备发布，需要核对说明与实际能力是否一致。",
  "requirements": "核查发布声明，指出缺少依据或与代码不符的事项。",
  "acceptanceCriteria": "每项问题给出可定位的证据；无法确认的内容明确标注。",
  "resultSchema": {
    "type": "object",
    "properties": {
      "summary": { "type": "string" },
      "findings": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "claim": { "type": "string" },
            "evidence": { "type": "string" }
          },
          "required": ["claim", "evidence"],
          "additionalProperties": false
        }
      }
    },
    "required": ["summary", "findings"],
    "additionalProperties": false
  }
}
```

材料通过 `MaterialRef` 保留身份、内容摘要和可读取位置。接收者读取任务后，可通过 `flow_material_read` 获取宿主能够呈现的文本、图片或文件；读取仍遵循宿主权限。

## 派发与父子关系

会话 Agent 通过入口服务向团队根派发顶层作业。树内正式作业只向当前直属子 Agent 派发，并明确所服务的上级作业。运行时检查上级作业仍未结束，其接收者正是本次派发者。

`AssignmentService.prepare` 验证并保存任务、关系、schema 与材料；`deliver` 将完整任务及提交要求作为 System 消息送入接收者的 Mailbox。准备记录不会启动模型，交付完成表示消息已入箱。

Agent 树记录组织关系，作业树记录任务拆分。一个 Agent 可以同时接收多份作业，自己决定处理顺序。运行时分别管理这些记录。

## 提交与完成

接收者通过 `flow_submit` 提交结果。提交前，先取消已经不需要的子作业；仍要继续的直接子作业，需要逐项给出非空存续理由，随 `continuingChildren` 提交。运行时按提交时的最新子作业状态检查，缺少理由时返回相应 ID。

子作业处置检查通过后，运行时检查结果 schema。首次格式失败后固定允许两次纠正，即最多三次格式提交。错误在工具调用中返回字段路径和原因，由 Agent 自行修正。子作业存续理由等前置检查失败不消耗格式纠正机会。

首份格式合格且保存成功的结果使作业进入 `submitted`。派发者随后判断内容是否符合需求和验收标准，必要时通过沟通或新作业补充。

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未结束，包含执行、等待处理及格式纠正。 |
| `submitted` | 结果通过检查并保存，作业完成。 |
| `failed` | 格式纠正机会用尽、接收者终止或交付失败。 |
| `cancelled` | 已取消，不再接受结果。 |

## 取消与通知

真实发送方可以取消自己派发的作业。运行时沿作业父子关系遍历，递归取消所有未结束后代，即使路径中存在已完成的中间作业。已保存结果继续保留。

取消作用于作业，不终止接收 Agent，也不影响它承接的其他作业。接收者通过取消通知得知应停止相应工作。已经发生的模型调用和外部操作作为执行事实保留。

完成、失败等异步终态通过既有消息机制通知仍活跃的发送方。顶层作业完成后，入口服务向会话 Agent 提交 `followup`，由会话 Agent 读取实际结果并向用户汇报。

## 历史与继续工作

持久记录保存任务内容、schema、材料、派发关系、提交结果和子作业存续理由。冷恢复后，已保存结果可查询，未完成记录保留其中断事实。

继续旧工作时，先恢复会话及当前组织关系，再派发新的顶层作业和子作业。通过 `resumesAssignmentId` 关联历史来源，同时建立当前作业关系。会话恢复不会自动重新绑定或重发历史作业。

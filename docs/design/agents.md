# Agent 与组织关系

Agent 是 Flow 中独立执行任务的智能体实例。会话保存对话历史和配置，以 `SessionID` 标识；Agent 是当前编排环境中使用该会话工作的对象。宿主适配器把 Flow 的执行请求交给原生 Agent，`Context` 负责登记、查找和释放运行时对象。

## 身份与父子关系

`AgentProfile` 在创建时确定身份提示词、显示名称、会话身份、初始权限、模型、推理参数及宿主附加配置，并在实例生命周期内保持不变。

父子关系表示逻辑管理关系。父 Agent 管理直属成员，向它们派发正式作业，并沿当前树传播终止控制请求。每个成员的会话、信箱、工具绑定和执行资源归属自身。信箱（Mailbox）保存收到的消息及读取状态。

团队根的父级为 `null`。与用户对话的会话 Agent 位于团队树外，通过入口服务管理一棵或多棵团队树。各级成员可以继续扩展子树，树的高度由组织需求决定。

## 创建与恢复

| 操作 | 输入与结果 |
| --- | --- |
| `Agent.create` | 使用给定 Profile 创建新会话及 Agent，可导入对话快照。 |
| `Agent.resume` | 从持久化会话恢复对话及配置，建立新的 Agent 实例。 |
| `fork` | 以当前 Agent 为母版，复制配置与对话快照，创建逻辑子 Agent。 |
| `herb` | 分别总结调用方和另一 Agent 的上下文，合并后创建调用方的逻辑子 Agent。 |

这些操作成功返回时，宿主实例、Mailbox、工具、事件订阅、父子关系及 Context 登记均已就绪。`Agent.create` 提供 `initmsg` 时，在初始化后提交初始输入；省略时创建空闲实例。调用返回只表示输入已由宿主接管，模型可以继续执行。

冷恢复使用持久化的完整 Profile，逻辑父级由本次参数建立。通信环境重新初始化：Mailbox 为空，过滤规则、来源评级、主动等待和群成员资格需要重新建立。恢复说明随下一次模型请求进入上下文，帮助 Agent 区分会话历史与当前可用的协作者。

## 执行与状态

宿主把执行划分为轮次（turn）和轮次内的步骤（step）。模型在步骤中生成文本或请求工具，宿主执行工具后继续推进。Flow 通过适配器的 `turn-end` 事件确认轮次结束。

| Agent 状态 | 含义 |
| --- | --- |
| `running` | 正在执行工作。 |
| `waiting` | 已登记主动等待，等待协作者的匹配消息。 |
| `idle` | 实例存活，没有进一步工作请求，也没有未完成的主动等待。 |
| `terminated` | 逻辑生命周期已结束，不再接受新业务请求或被消息唤醒。 |

作业状态单独记录。一个 Agent 可以完成某份作业后继续运行，也可以暂时空闲并等待后续任务。主动等待期间，优先消息可触发临时执行，原等待条件仍然有效。

## 转移与上下文派生

`transfer` 更新逻辑父级，保留 Agent 的身份、会话、Mailbox、权限和当前执行。后续新作业按新的直属关系检查；既有作业保留已登记的发送方、接收方及上级作业。

`fork` 使用母版的对话快照作为新会话起点。`herb` 先由双方各自的模型总结上下文，再用调用方的模型合并两份总结，保留来源、约束、进展和未解决分歧。总结与合并使用独立的辅助请求，生成的结果用于新子 Agent。

派生实例取得新的 `SessionID`，按母版 Profile 创建。辅助调用用量在子节点建立后计入子节点；派生失败时计入调用方。总结格式见 [上下文派生模型](design.md#上下文派生模型)。

## 终止与释放

终止先结束逻辑生命周期，再执行资源收尾。收到终止请求时，Agent 撤销主动等待、退出所属群，并按当前父子关系向后代传播请求。

| 收尾方式 | 行为 |
| --- | --- |
| `after-turn` | 拒绝新的执行步骤，允许关闭前已经开始的轮次收尾，再持久化并清理资源。 |
| `immediate` | 撤销当前轮次的业务资格，取消执行，尝试持久化后清理资源。 |

`SIGTERM` 对应 `after-turn`，`SIGKILL` 对应 `immediate`。优雅收尾默认时限为 120 秒，超过时限且尚未进入资源清理时升级为立即清理；立即清理默认时限为 10 秒。重复请求合并到同一次关闭操作。

看板分别呈现逻辑终止结果与清理进度。释放操作的 Promise 完成表示约定的资源处理已结束。完整的关闭时序及失败含义见 [生命周期模型](design.md#生命周期模型)。

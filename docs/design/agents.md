# Agent 实现与角色

标准 DSH Agent 是实现层的统一执行单元；协调者和执行者是角色层的两类职责身份。用户看到的是不同角色的 Agent 协作，这些 Agent 均使用原生模型、上下文、工具、技能、权限和 Session。角色不等同于工具权限等级。

当前主会话在其团队中承担协调者（Orchestrator）职责，负责分工、验收、汇总和最终交付。委派时可以声明成员为协调者或执行者（Worker），未声明时按执行者配置。根据已接受的 ADR 0005，原 Allocator 的资源选择和任务分配职责归入 Orchestrator。研究、核验、写作等用成员名称、职责说明与 skills 细化，不增加新的通用角色。Controller 的容量排队属于程序调度。

`flow_task.profile` 包含可选的名称、角色、职责说明、原生 preset、模型和 skills。职责通过原生系统提示组合，skills 通过宿主 registry 解析。配置随成员保存，供恢复和界面读取；具体参数见[Agent 配置](/configuration/agents)。`role` 只接受 `orchestrator` 和 `worker`，表示职责，不选择执行引擎或工具权限。

会话归属、角色与当前任务分别记录。同一成员可以承担多个连续任务，也可递归委派；协调者不必位于拓扑根部，执行者也可以协调其子任务。验收权来自实际委派关系，不通过角色名称判断。

已有主 Agent 持有根任务，创建团队不重复启动根成员；真正委派才创建成员。正常回合结束保留 AgentHandle，真正关闭才回收。团队结束仅清理 Flow 创建的成员，主会话继续可用。

界面显示角色及职责，同时分别呈现业务任务状态和原生执行状态。创建配置不是实际调用证据；实际 provider/model、工具调用与用量以原生日志为准。

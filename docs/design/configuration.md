# 配置与权限

配置决定新团队和成员使用的角色、模型、工作目录、权限及运行资源。DSH 中的可编辑值来自宿主配置，表单显示当前值与继承来源；清空覆盖或恢复继承后，继续使用上层值。

## 角色与运行默认值

团队根采用发起会话的模型与未覆盖配置，运行默认值提供显式覆盖。创建成员时，依次采用运行默认快照、模板角色配置和本次显式覆盖。已经创建的 Agent 保持自己的 Profile。

角色可以提供职责、预设、附加技能、模型和推理参数。`team-strategy` 是所有 Flow 节点的默认技能，模板无需重复列出。模型与推理参数采用宿主无关的声明，由适配器检查能否实际落实。

## 生效时机

| 配置组 | 内容 | 生效时机 |
| --- | --- | --- |
| 运行与角色默认值 | 职责、预设、附加技能、模型、推理参数、工作目录和初始权限 | 新运行开始前解析为快照，后续成员按该快照及角色配置创建。 |
| 模板来源 | `patternSources` 指定内置包以外的目录 | 加载时检查并展示可用模板，创建成员时读取选定定义。 |
| 执行容量 | `maxConcurrentAgents`，默认 `4` | 保存后影响后续执行准入，当前执行继续完成。 |
| 清理时限 | 优雅收尾默认 120 秒，立即清理默认 10 秒 | 进入新运行快照，由编排层与适配器共同使用。 |
| 服务连接 | 端口、状态目录、静态目录、允许来源和价格表 | 保存后提示重启，由用户重启服务后生效。 |

执行容量约束能够同时执行的 Agent 数量。团队规模由模板参数决定，一个 Agent 持有的作业数量由任务安排决定；这些对象分别记录和管理。

## 初始权限

| Flow 权限 | 含义 | DSH 沙箱模式 |
| --- | --- | --- |
| `read-only` | 只读文件访问 | `read-only` |
| `workspace-write` | 工作区内读写 | `workspace-write` |
| `full-access` | 完全访问 | `danger-full-access` |

父级创建子 Agent 时，根据任务所需操作选择初始权限。子级初始权限不得高于逻辑父级 Profile 中记录的初始权限。工作区边界由宿主适配器安装；`fork` 和 `herb` 继承母版的权限值，由新实例独立安装。

运行中权限不足时，由成员报告受限事项，父级重新分配任务或创建具有适当权限的新 Agent。Flow 的 Profile 记录初始权限；适配器尽力关闭宿主升权入口，运行中的权限变化仍由宿主执行机制决定。

冷恢复重新安装持久化的初始权限和工作区边界。恢复为子 Agent 时，重新检查与新父级的权限关系。

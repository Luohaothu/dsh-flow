# 欢迎

**dsh-flow** 是基于 DeepSeek Harness（dsh）的层次化智能体集群系统。它将复杂目标分解为可以独立验收的任务单元，通过管理树分配责任，让不同分支直接协作。独立审计负责复核决策和验收结论，预算账本记录资源用量，持久化记录保存执行证据。

每个管理节点由三类角色组成：**编排智能体**负责规划任务和验收结果，**资源分配智能体**负责选择执行者、分配资源，**审计智能体**负责监督规划和复核验收结论。具体工作由**执行智能体**完成；需要进一步分解和协调的工作，则交给下级管理节点。

## 先区分三个概念

| 概念 | 包含什么 | 怎样才算完成 |
|---|---|---|
| 任务单元 | 目标、输入、约束、依赖与验收标准 | 结果通过业务验收和独立复核，并被正式接受 |
| 智能体 | 身份、角色、会话与工具能力 | 本次执行结束并完成结算；任务结果仍须另行验收 |
| 管理节点 | 三类管理角色，以及直接负责的任务单元和子节点 | 完成本管理域的交付和资源归还，并保存必要的管理与审计记录 |

管理树说明“谁对谁负责”，任务依赖图说明“哪些工作必须先完成”，通信图说明“谁在与谁交换信息”。跨分支通信不会自动授予调度或验收其他管理域任务的权限。

## 设计范围与实现边界

每个管理节点只直接管理有限数量的子节点；复杂工作逐级委派，各级分别规划、分配资源和审计，再向上提交摘要。身份数量、活跃身份、Agent 调度许可和深度均受独立限制，实际业务容量取决于任务、模型、工具预算与部署条件。

系统设计页面介绍角色、执行状态和关键约束，配置和 API 页面介绍可用的参数与接口。[动作索引](/development/action-catalog)按角色解释操作职责，[主会话与团队界面](/development/interface)说明实际交互边界。运行时复用 dsh 的智能体、会话、工具执行和远程接口机制，不另外实现一套智能体执行循环。

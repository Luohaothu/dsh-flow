# 成员消息

`message` 指定接收成员、正文和可选任务关联。request 请求继续或回复；notice 提供信息。协作智能体提供自身发送方法，调用者身份由会话绑定。

## 通信交接

每个协作智能体把自身异步接收回调注册到消息队列。发送方保存消息并提交队列后返回。消息队列按接收会话寻址，调用对应接收回调；接收回调记录接管，并负责将消息提交给自身原生智能体。

消息队列只维护通信交接，不查询智能体是否正在执行，也不负责智能体启动、暂停或关闭。自身原生执行状态由接收智能体维护。

## 执行调度

收到 request 后，接收智能体处理自身输入。已有活动通过原生 steer 接收；需要启动的执行工作由系统封装为作业，提交智能体执行队列。notice 通过原生 inject 提供信息。

智能体执行队列管理固定数量的并行执行单元，决定作业何时启动。同一会话的作业串行执行。智能体不查询队列容量；排队与占位状态只在系统内部维护。原生 Inbox 和 Session 继续负责输入及模型步骤。

## 消息记录

| 记录 | 含义 |
| --- | --- |
| 入队 | 消息已持久保存，发送操作完成。 |
| 接管事件 `message-received` | 接收回调已承担后续处理，通信交接完成。 |
| 交付状态 `delivered` | 原生会话出现带该消息身份的 `user/message` 事件，确认输入已进入会话。 |

发送返回入队结果，不等待接收回调或原生交付。接管不将消息改为 `delivered`；该状态由接收智能体根据原生会话事件确认。

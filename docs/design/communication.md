# 消息与协作

消息连接协作者，Mailbox 保存每个 Agent 实际收到的内容。Agent 负责整理通知，宿主适配器把通知提交给模型，模型再通过读取工具取得正文。消息入箱、通知被宿主接管和正文已读分别记录。

## 选择交流方式

| 方式 | 适合的用途 | 处理约定 |
| --- | --- | --- |
| 点对点消息 | 询问进度、澄清需求、交换线索 | 交给目标 Agent 的 `recvMessage`。 |
| 群聊消息 | 向一组协作者广播讨论内容 | 由 Group 向发送者以外的成员投递。 |
| 群黑板 | 追加和读取共享资料 | 成员通过 Group 访问，同一时间最多一个子 Agent 追加。 |
| 正式作业 | 委派需要状态追踪和格式检查的任务 | 按直属父子关系派发，运行时记录与校验。 |

请求对方按要求返回内容时，一并说明返回格式和验收标准。跨分支讨论使用消息或群聊，不改变团队的管理关系和作业父子关系。

## 消息来源与优先级

消息包含来源、时间、摘要和正文。来源可以是用户、系统、Agent，或同时标明 Agent 与 Group 的群聊来源。优先级由接收者对来源的评级确定；未评级来源首次按 `normal` 处理，通知同时提示接收者进行评级。

| 优先级 | 通知安排 | 通知内容 |
| --- | --- | --- |
| `high` | 立即以 `steer` 提交，在可接收输入的步骤处理 | 消息 ID、来源及摘要。 |
| `normal` | 轮次结束后汇总；空闲且没有主动等待时立即汇总 | 逐条列出消息 ID、来源及摘要。 |
| `low` | 并入普通汇总批次 | 只报告不重要消息的数量。 |

接收方的 Mailbox 按自身规则过滤消息，并独立记录已接收消息的优先级和已读状态。来源评级可随任务变化调整。一次通知被宿主接管，只推进该批次的通知进度；正文是否已读由读取操作决定。

## 轮次与输入模式

宿主将执行划分为轮次及轮次内的步骤。Flow 提交输入时指定处理时机：

| 输入模式 | 含义 |
| --- | --- |
| `followup` | 下一轮处理，并唤醒空闲 Agent。 |
| `steer` | 在下一可接收输入的执行步骤处理，并唤醒空闲 Agent。 |
| `notice` | 插入后续步骤，不主动唤醒 Agent。 |

普通消息通知使用 `followup`，优先通知使用 `steer`。通知由 Agent 按已入箱消息构造，适配器保留其用途和级别，用于执行准入与会话恢复。

## 群聊与共享黑板

Group 在创建时确定成员。其存续期间成员集合不新增或替换；成员逻辑终止时自动退群。需要调整协作组织时，Agent 可以创建新群或解散旧群。

群聊消息进入各接收成员自己的 Mailbox，Group 不另存消息历史。解散群会解除成员关联并释放黑板，成员 Mailbox 中已经接收的群消息继续按原有生命周期保留。

黑板保存追加的消息记录，时间戳由 Group 分配，并在同一黑板内严格递增。`readBlackboard(t)` 读取指定时间戳之后的记录，`hasNewMsgOnboard(t)` 查询是否有更新。写黑板不会自动投递消息；需要提醒协作者时，另外发送普通消息。

## 主动等待

Agent 通过等待工具指定协作者和消息条件。Flow 原子地检查已有未读消息，并在没有匹配时登记等待。

| 返回结果 | 后续行为 |
| --- | --- |
| `matched` | 返回匹配消息的元信息，继续当前轮次。 |
| `registered` | 返回等待已登记，结束当前轮次，等待后续消息。 |

期限内收到匹配消息时，解除等待并提交完成提示。匹配消息可以是普通或不重要消息，仍能及时结束等待。等待期间的普通通知暂缓，并在恢复时与完成提示合并处理。

无关的优先消息可以临时唤醒 Agent，原等待和截止时间继续保留。超时则由 Flow 发送优先系统通知，说明等待目标、发起时间和时长，由 Agent 决定下一步。

## 终止控制

`Signal` 沿 Agent 父子树传递终止请求，直接交给 `recvSignal` 处理。`SIGTERM` 采用优雅收尾，`SIGKILL` 采用立即清理；两者都立即向当前后代传播。控制信号与业务消息分别处理，具体时序见 [终止与释放](agents.md#终止与释放)。

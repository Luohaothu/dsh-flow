# 高级使用

完成[快速上手](/quick-start)后，可以按本页的方法组织较复杂的任务。点击侧栏的 **Cluster**（集群），查看任务分工、运行进度和验收结果。面板属于当前 DSH 配置方案，打开不同会话时仍可能看到同一批集群；操作前先确认选中的集群 ID 和目标。

## 把任务写成可以验收的要求

集群会自行拆分任务、分配执行智能体并审查结果。你需要交代清楚要解决什么问题、可以使用哪些材料，以及什么样的结果才算完成。

| 要素 | 建议写明的内容 |
| --- | --- |
| 目标 | 要得到什么结果，以及结果供谁使用 |
| 工作目录 | 本次任务使用的绝对路径 |
| 输入材料 | 需要阅读的文件、数据或网页，以及应优先依据的版本 |
| 交付物 | 文件名称、保存位置、格式和必要内容 |
| 修改范围 | 允许修改哪些文件，哪些内容需要保留 |
| 验收条件 | 可以逐项检查的要求；需要运行检查时，写明检查方法 |

例如，下面的任务既限定了修改范围，也说明了如何判断结果是否合格。提交前，将示例路径换成自己的实际目录。

```text
工作目录是 /absolute/path/to/project。

请阅读 README.md 和 docs/api.md，为首次使用本项目的人编写一份入门指南，
保存为 docs/getting-started.md。

指南需要包括环境准备、启动步骤、一个完整示例和常见问题。
现有资料没有说明的内容请标为待确认，不要补写未经验证的命令。
只允许新增或修改 docs/getting-started.md，保留其他文件。

验收条件：
1. 文档中的每一步都说明输入、操作和预期结果。
2. 示例中的参数与 docs/api.md 一致。
3. 所有本地文件链接都指向实际存在的文件。
4. 最后列出待确认事项及其原因。
```

尽量把“做得完善”“质量要高”换成具体检查项。任务依赖多个材料时，也要说明它们冲突时以哪个为准。已有成果可以作为输入，但应明确哪些结论需要重新验证。

开始任务前，把目标、工作目录和权限交代清楚。需要处理不同目标时，创建新的集群，便于分别跟踪进度、核对用量和验收结果。

## 选择工作目录和权限

工作目录应指向本次要处理的项目或材料目录。通过面板创建集群时，在 **Workspace**（工作目录）中填写绝对路径，任务描述中的路径也应与它一致。集群运行记录的保存位置由启动配置决定，与交付文件的保存位置分别设置。

根据任务需要选择能力。例如，只检查已有资料时使用文件读取能力；需要生成文档时再加入文件写入能力；运行测试或其他命令需要命令执行能力。能力名称、对应工具和宿主要求见[智能体配置参数](/configuration/agents#能力与工具范围)。

插件本身的默认能力包括文件读取和文件写入；快速上手提供的配置将默认能力设为空，以运行纯计算示例。处理文件或命令类任务前，应确认 DSH 提供了对应工具，再在创建集群时授予所需能力。如果任务要求只读，只授予读取能力。面板中的 **Capabilities**（工具能力）使用逗号分隔能力名称；该表单初始填有文件读取和文件写入能力，纯计算任务应清空此字段。

[快速上手](/quick-start)提供的启动配置会将当前配置方案中新会话的默认权限设为允许工作区写入、不请求审批，也会影响普通会话；已有会话保留先前记录的权限。这项设置保持 `workspace-write` 沙箱约束，需要审批的操作直接拒绝，并不意味着允许任意操作。

任务文字中写明“只改这个文件”，有助于规划和验收；实际可使用的工具还取决于创建时的能力和 DSH 的权限设置。指定工作目录本身不等于建立操作系统级的文件隔离。浏览器等能力还需要宿主提供相应工具，填写能力名称不会自动安装或连接它们。

## 安排预算与并发

预算需要覆盖完整交付过程：除了执行任务，还包括规划、资源分配、独立审计、上下文压缩和必要的返工。因此，预算接近耗尽时，即使已经生成文件，也可能没有足够额度完成验收。

通过面板创建集群时，可在 **Budget override (JSON)**（预算覆盖配置）中填写 JSON 配置，调整本次任务的额度；留空则沿用启动配置中的默认值。快速上手示例将整个集群的运行时限设为 30 分钟，实际也可能因其他额度耗尽而提前停止。各项预算的含义和默认值见[集群配置参数](/configuration/cluster#默认根预算)。先用范围清楚的小任务观察实际用量，再为更复杂的任务设置额度，比直接扩大智能体数量更容易判断成本。

并发适合处理彼此独立的工作，例如分别检查不同模块。多个任务需要修改同一份文件，或者后续工作必须等待前一步结果时，提高并发未必能缩短完成时间。

选择并发配置时，需要区分三件事：可以创建多少个智能体、同一时间允许多少轮执行、同一时间允许多少个模型请求。三类管理角色也占用智能体数量额度。提高并发或数量上限不会增加 Token、模型请求或工具调用预算；具体参数见[运行限制](/configuration/cluster#默认-limits-与取值范围)。

运行中可在 **resources**（资源）页查看预算和用量。某个节点缺少额度时，资源分配智能体可以在授权范围内重新分配可用额度，但不会增加整个集群的总预算。若需要用更高预算重新开始，应先保存已有成果、结束旧任务，再明确哪些工作需要继续完成。

## 暂停、继续与取消

在集群列表中选中目标集群，使用面板顶部的 **Pause**、**Resume** 或 **Cancel**。操作后查看状态和提示，确认所选集群已响应操作。

| 操作 | 适用情况 | 实际效果 |
| --- | --- | --- |
| **Pause**（暂停） | 暂时停止派发新工作，检查当前进展 | 停止新的调度；已经开始的执行轮次仍可能继续并产生结果 |
| **Resume**（继续） | 继续已暂停的集群，或在解决阻塞原因后继续 | 重新允许调度；后续执行仍受依赖、预算、权限和恢复检查约束 |
| **Cancel**（取消） | 不再继续当前目标 | 取消尚未结束的工作并中止正在执行的轮次；集群进入已取消状态（`CANCELLED`） |

暂停不会撤销已经发生的操作，也不会冻结按实际经过时间计算的任务时限。点击 **Resume** 不会重置已用预算或延长截止时间。若暂停较久后任务无法继续，先查看是否已超过时限。

取消同样不会撤销已经写入的文件或已经发生的外部操作。已完成、已失败或已取消的集群不能通过 **Resume** 重新启动；需要继续时，应创建新的任务并说明已有成果的使用方式。

### dsh 重启后如何处理

关闭浏览器页面不等于暂停或取消集群；需要停止工作时，应使用上述操作。若 dsh 重启，插件会根据保留的运行记录和会话记录检查哪些工作可以继续。重新打开 **Cluster**，找到原集群并确认状态。

重启后，系统需要先确认中断前的工作是否已经完成。会话记录缺失、用量无法核对，或者文件写入、命令执行等操作的结果尚不明确时，相关工作会暂时阻塞。此时应保留数据和已有产物，由维护人员核对后再继续，避免重复执行同一项操作。

## 验收结果和查找问题

### 判断是否完成

执行智能体提交结果后，任务单元还需要通过编排智能体的业务验收和审计智能体的独立审查，才能进入 **已接受** 状态（`ACCEPTED`）。需要交付的任务单元完成后，集群还要完成汇总和收尾，才能进入 **已完成** 状态（`COMPLETED`）。

验收时，先在面板顶部确认集群状态，再打开 **transactions**（任务单元）页，点击具体任务查看结果和验收情况。最后还应打开实际产物，逐项核对最初的要求；“文件已生成”或部分任务通过验收，都不代表整个目标已经完成。

### 从现象找到检查入口

| 现象 | 先检查什么 | 接下来怎么做 |
| --- | --- | --- |
| 长时间没有开始执行 | 集群状态、任务单元状态和面板中的失败原因 | 确认是否暂停、等待前置结果，或受到预算与运行限制约束 |
| 结果已提交，仍未通过验收 | **transactions** 中的验收情况、审查结论和纠正要求 | 区分等待审查、需要返工和运行阻塞；不要把“已提交”当成“已完成” |
| 提示预算不足或超过限制 | **resources** 中的已用和已预留额度，以及 **Failure detail** 中的原因 | 确认是总预算不足、局部额度不足，还是时间、轮次或并发限制；点击 **Resume** 不会自动增加额度 |
| 提示上下文压力 | **context** 中的上下文用量和压缩记录 | 联系维护人员检查模型上下文设置与压缩配置；再次启动时可缩小任务范围、精简输入材料 |
| 模型或工具无法使用 | 错误提示、所需能力和宿主配置 | 确认模型服务、工具和权限已准备好；只有任务文字中的授权不足以让工具可用 |
| 重启后保持阻塞 | 失败原因是否涉及缺失会话、用量不明或操作结果不明 | 保存报告并核对实际产物，避免重复执行结果尚未确认的操作 |

面板提供六个页签：**tree** 查看管理树，**transactions** 查看任务单元，**communication** 查看协作消息，**context** 查看上下文用量与压缩记录，**health** 查看编排履职情况，**resources** 查看预算与用量。进入 **tree** 后点击 **Load root**，再逐层展开节点。面板底部的 **Events** 显示近期事件；遇到问题时，先查看运行提示和对应任务单元，再按需要查看其他记录。

### 保存排查材料

点击 **Download report**（下载报告），保存所选集群的运行与验收摘要。需要排查问题时，再记录集群 ID、错误提示、发生问题的大致时间和相关产物，并说明原始目标、工作目录、期望结果与实际结果。

报告用于保存摘要，交付文件仍需单独保留。继续使用同一实例时，应从原工作目录启动，并保留集群数据目录和 dsh 的数据目录，以便查看历史记录和处理未完成任务。面板中显示为未知（`unknown`）的用量或检查结果，表示尚无足够记录，不能当作零用量或检查通过。

# Agent 角色与原生配置

角色描述职责，标准 DSH Agent 提供执行基础。使用 `flow_task` 委派新成员时，通过可选 `profile` 配置身份和原生执行参数；无需增加角色专用执行器、工具白名单或另一套调度协议。

| 字段 | 含义与默认值 |
| --- | --- |
| `name` | 成员名称，独立于任务标题；省略时使用标题或目标摘要。 |
| `role` | `orchestrator`（协调者）或 `worker`（执行者）；省略为 worker。主会话在自己的团队中承担协调者职责。 |
| `instructions` | 持续职责，组合到原生系统提示。一次工作的具体要求仍放在 `objective`。 |
| `preset` | 已安装的 DSH 原生 preset；省略时使用团队配置，未配置时由宿主继承父会话组合或使用默认值。 |
| `model` | 原生 provider/model/reasoningEffort 选择；指定字段覆盖团队创建模型配置，其余跟随团队或宿主。冷恢复尊重原生会话保存的后续选择。 |
| `skills` | 已安装、允许模型调用的技能名称。在成员作用域和工作目录中由原生 registry 加载，使用官方内容渲染器组合为角色指令。省略不会移除 Agent 正常可用的 skills。 |

```json
{
  "action": "delegate",
  "title": "核对行情来源",
  "objective": "核对已提供行情数据的日期与口径，将证据写入 output/sources.md。",
  "profile": {
    "name": "行情研究",
    "role": "worker",
    "instructions": "负责来源核验，保留原始来源和统计口径，说明未解决的差异。"
  }
}
```

需要一个子协调者管理独立目标时，委派 `role: "orchestrator"`。该角色的默认职责包括规划、资源选择、分配、验收和汇总；worker 的默认职责是执行和交付，也可继续委派。原 Allocator 职责归于 Orchestrator，研究、核验等专业分工写入 name、instructions 和 skills。角色配置不扩张权限，也不触发额外成员。

创建配置保存于成员记录。复用成员（`member_id`）保留原配置，不能同时传 `profile`；修改任务也不能重配成员。需要另一组持续职责或执行配置时，显式委派新成员。正常的原生会话模型/preset 调整仍由宿主处理。

职责和 skills 在创建或冷恢复时组合，不增加模型回合或初始化工具调用。找不到技能或技能仅允许用户调用时，成员明确报错；不会忽略配置或绕过宿主调用策略。技能正文由宿主当前 registry 解析，名称持久化不表示冻结技能内容。

模型参数、压缩、业务工具、sandbox 和审批由 DSH 处理。新插件工具可通过原生组合直接使用，Flow 不增加能力枚举或工具名称映射。任务分工、角色名称和目录说明不会改变权限。DSH 启动 profile 与此处的成员角色配置是不同层次；后者通过前者安装的原生接口生效。

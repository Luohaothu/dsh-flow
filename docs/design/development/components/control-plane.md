# 协作控制

Controller 保存团队归属、任务委派、当前结果、接受记录和成员消息。真实 Session 身份决定可操作范围；成员不能冒用委派者接受自己的交付。

调度遵守配置的 Agent 容量、用户明确期限、任务暂停与同一 Agent 的原生活动互斥。候选任务按持久化行序选择，委派立即返回。上一成果待接受不会继续占用执行槽；修订排队任务不会取消无关的活跃工作。

父任务从本团队归属推导：所有者使用本团队根任务，成员使用当前任务。同一个原生 Agent 可在不同团队分别拥有根任务和执行成员任务。Controller 不裁剪原生能力，也不保存预声明依赖等待图。

需要维护的协作事实是操作幂等、真实 actor、任务版本、当前 Result、委派者决定和子任务义务。正常成员返回在 idle 与 flush 后发布可检查结果；ready 不是自动接受，也不保证该 Agent 以后不会再次运行。显式 partial/blocked 不会被普通最终正文覆盖。

根结果、根任务 ACCEPTED 和团队 completed 在同一事务提交，未接受或取消的子任务使该提交整体拒绝。团队完成只回收 Flow 创建的成员，不停止原生主会话；逻辑完成与异步资源排空分开观察。

执行状态来自原生 Agent。Flow 不依据周期事件或自定义“进展”分数唤醒和终止模型。

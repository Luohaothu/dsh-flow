## 真实 Web 会话

通过用户可见的技能候选选择 `/agent-team`，输入简短的四人团队库存核对任务。主会话与四个真实成员均使用测试模型 B；业务工作区只包含 CSV 和业务说明，预期结果位于工作区之外。

- 主会话创建一个团队，负责人建立 author、critic、verifier 三名直属成员，共四人。作者计算并生成报告，两名只读成员分别审查口径与独立复算，作者完成措辞修订后再次核验。
- 六份正式作业均达到 `submitted`。主会话收到终态通知，读取实际提交和文件后交付最终结果。
- 独立核对结果：A/C/D/F 分别补货 12/4/28/30 件，B/E 为 0，合计 74 件；风险项为 C、D。输入文件未被改写，报告已经落盘。
- 完成后从产品界面解散团队；运行显示已解散，四个节点均显示已停止、清理完成，运行记录为 `stopped`、`cleanup=complete`，历史与提交结果保留。

该案例验证了指定人数及实际协作交付。它采用负责人加三个直属成员的结构，没有覆盖内置 `hierarchical` 的多层研究团队，也不计入自主选择模式的自然场景覆盖。内置层级模板按固定角色展开，人数为 `2 + groups × (membersPerGroup + 3)`，不能恰好表达四人；其独立 API 展开已在本地工作流测试覆盖。

原生日志记录 104 次对话 generation、4,880,175 个已报告 tokens；另有一条标题请求的完成与用量未知。原生记录未提供可数的物理 HTTP 请求或内部重试次数，不能把 generation 当作该指标。历史物理请求账目保持原口径。

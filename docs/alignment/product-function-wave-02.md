# 产品功能测试波 02

本波在 `808607fe` 上使用官方 Web 宿主和普通 `/agent-team` 业务需求，开展四个真实案例。发现独立 profile 不构成读取隔离后停止本波，保留已经完成的局部结果。原始会话与产物保留本地，本文不公开接入配置或实际服务名称。

## 业务与协作结果

| 案例 | 实际结果 | 验收边界 |
| --- | --- | --- |
| N17 发布核查 | 对六处冲突、缺失证据与批准条件给出结论和沟通稿，保留正式发布与内部演练的区别；原始材料未改写 | 业务核对通过。已有用户模板未被应用，不计模式覆盖 |
| N18 金额工具 | 修正为只计已结算订单并计入运费，结果为 1045 分；客户断言未改写 | 独立副本回归为 2 通过、0 失败、1 个既有跳过，另有 8 项边界核对通过。未应用无关模板，不据此推断已显式比较其适用范围 |
| N19 可复用模板 | 形成模板包和使用说明，同版公开目录加载器无诊断，污染前同一 Run 内两次应用分别新增 3、5 人 | 主会话越过案例目录，读取其他案例配置及预留后续提示。完整自然验收和跨 Main 复用无效，后续材料未投放 |
| M07 跨模块方案 | 形成一致方案、验收表与样例，覆盖金额、时区、字段、状态、revision、职责交接和盘点边界 | 主要业务点已覆盖，但包含无依据的重试断言，不能记为业务准确性全部通过。只查询模板目录，未应用模式 |

四个案例的正式作业提交数依次为 1、1、3、3。主会话收到结果通知并读取交付。停止后，四份运行记录均为 `stopped`、`cleanup=complete`，四个官方 Web 进程均通过普通中断退出，保留历史记录。空闲示范成员不计有效协作规模。

M07 的输入只规定 `(receipt_id, revision)` 是重试键，以及 revision 增加表示有效更正。交付却断言每次重试都产生新 revision，主会话验收未指出缺少来源。该问题记为生成与验收质量遗漏，不能据此认定后端去重实现有缺陷。

## 问题与隔离修正

- [#89](https://github.com/Luohaothu/dsh-flow/issues/89) 记录测试配置缺陷。不同 profile、状态目录和工作区仍共享操作系统读取权限。N19 实际读到了另一案例的配置片段、工作区登记正文及预留提示正文；oracle 文件仅被列出，未证明正文被读取。受污染步骤须使用新材料重跑，当前记录不补记通过。
- [#90](https://github.com/Luohaothu/dsh-flow/issues/90) 记录跨模块交付中的无依据断言及独立验收遗漏，等待定位合适的产品改进。没有为单个答案追加定向提示。

停止后使用正常 Docker 部署验证整个官方 SDK/Web 进程的文件系统隔离。本次部署检查仅挂载该检查实例的初始 profile、普通业务材料及只读产品包；宿主用户目录、其他案例和预留材料均不挂载。下一波按此方式逐案部署。SDK 使用普通用户运行，官方 Flow 面板已连接，业务文件可读，宿主路径不可见。验证未发送业务提示，正常停止容器的退出码为 0，随后移除该容器。没有新增外部控制器、请求代理或准入框架。

该部署检查证明下一次启动可采用正常文件系统隔离，尚未证明受污染业务步骤已经重测。#89 保持打开。

主会话与 Flow 分别记录 132、200 次 generation。消息 usage 与流结束 usage 核对后仅计一次。另有两次未报告 usage 的 TIMEOUT 重试事件和四条未报告 usage 的标题请求。实际失败代码均为 TIMEOUT，未观察到可确认的 429。

原生日志不能还原物理 HTTP 次数及全部内部重试，故不将 generation 与历史物理请求次数相加。前两次产品测试波合计 436 次对话 generation、34,149,986 个 reported tokens。连同历史已报告用量，已知 token 合计为 126,052,477；未知用量保持未知，不设 token 上限。

## 剩余验收

本波未取得完整独立的自然模式应用通过项，也未完成受污染模板的跨 Main 复用。N19 的落盘、加载及同 Run 局部实例化证据保留，不据此补记整案通过。下一波先验证用户简短指定模式与人数时的真实产品行为，并以新材料复测模板使用。后续自然场景、其余模式、群聊、上下文派生、大规模有效协作、完整 UI/Desktop 和统一版本三轮验收继续保留，不以本波局部结果替代。

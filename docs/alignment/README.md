# 设计对齐实施

本目录记录按 design.md 重建实现的 P0 至 P7 阶段合同与实施裁决。每阶段单独创建 PR，完成独立评审及验收后合并，再开始下一阶段。

## 设计与代码基线

[design.md](../design/design.md) 是唯一设计依据。现有代码、目录及测试没有保留优先权。设计未要求的产品组件通常删除，差异大的模块直接重写，不提供旧接口、配置、协议或持久格式兼容层。新实现仍须满足设计规定的跨重启记录、会话恢复、事件游标、来源身份及操作幂等。

[基线记录](baseline.json) 同时记录本地主分支之外的未提交实现和已合并主干。P0 没有把这批未审查的实现导入主干。私有恢复归档包含 211 个当前文件，另有 191 个相对本地 HEAD 已删除路径。已在空目录解包并核对全部文件摘要及删除事实。归档仅留在本机，JSON 记录摘要及恢复验证结果。

主干与原本地设计只在一处 UI 文字不同。本地旧句写重新发起整次运行，主干已写选择复用或创建团队再派发作业。双方明确的团队生命周期、作业与入口合同一致，实施按这些合同执行。P0 不修改设计文档。

## 合同与去留清单

- [目标合同](contracts.json) 记录设计章节、负责阶段和可观察验收结果。
- [组件清单](components.json) 覆盖主干和本地实现的并集，逐项登记删除、重写或待评估复用。
- [测试清单](tests.json) 登记旧测试、夹具和验证脚本的处置，以及对应的新合同场景。
- [阶段记录](phases.json) 记录依赖、阶段状态、评审与合并证据。
- [决定日志](decisions.tsv) 追加记录影响实现的取舍及验证证据。

[P0 验证记录](p0-verification.json) 是本阶段实际运行的历史回执，不限定后续合同数量。CI 未提供私有归档时不声称重跑归档恢复，输出的 restoredFiles 为 null。阶段状态采用 pending、in-progress、reviewing、merged；开始下一阶段前，前驱须有已合并状态及评审和合并证据。

组件清单中的 evaluate 不是保留承诺。实施阶段必须依据设计责任、实际宿主能力及新合同测试结清。宿主补丁按能力评估，已经由公开接口满足或没有目标需求的补丁删除。仓库工作流程指引作为实施约束管理，不因不属于产品设计而删除。

旧行为测试和专用夹具在所属阶段删除。仍符合设计的用例需重新确认预期后才能采用。新测试按合同、宿主集成、界面及完整场景组织，测试入口同步覆盖新目录。旧测试数量及报告不构成阶段门槛。

## 阶段与完成条件

## 重跑 P0 复核

在仓库根目录运行以下命令。

```sh
python3 scripts/verify-alignment.py
python3 -B -m unittest discover -s tests/alignment -p 'test_*.py'
```

需要再次核对私有恢复归档时，指定本机归档路径。脚本将归档解包到临时空目录，核对文件摘要和已删除路径，随后清理该临时目录。

```sh
python3 scripts/verify-alignment.py --archive /absolute/path/pre-p0-worktree.tar.gz
```

PR 的评审记录对应确定的提交。产生新提交后重新评审受影响内容，合并时再次核对远程头提交、检查结果和评审结论。合并完成以远程 PR 状态确认。

## P1 验证范围

[P1 验证记录](p1-verification.json)对应 C001–C035 的 Core 与 DSH 基础合同。新测试共 119 项：Core 77 项，真实 Host runtime 36 项顶层测试及 6 项子测试；另有 8 项清单校验器测试。真实 Host 测试使用未打补丁的 rc.2 服务、AgentLoop、ToolRuntime 和 JSONL，模型输出由确定性适配器提供。

当前构建导出 Core/Host ESM 模块和声明文件。完整插件入口、团队与作业服务、协议、界面及安装验收随 P2–P7 接入。原生观察和 API 所有权保护在 P6 按宿主缺口实现。总结格式与请求约束已检验，真实模型的语义保留效果在 P7 验证。管理工具拒绝使用实际 ToolRuntime 的同名动作探针，未修改真实插件配置；120 秒与 10 秒默认值经静态核验，状态转换使用短时限运行测试。

基础层审计及 PR 评审发现工厂回滚释放屏障、重入终止、错误入箱、冷恢复配置、宿主字段、总结格式与来源回写、测试断言有效性及释放后强保留等问题，均已验证并修复。后续阶段与 PR 进度在[跟踪 Issue](https://github.com/Luohaothu/dsh-flow/issues/8)记录。

## P2 验证范围

[P2 验证记录](p2-verification.json)对应 C036–C046。当前合同测试共 402 项，包含先前 119 项及新增团队与归档 191 项、作业与 schema 92 项。`pnpm test:schema` 另检查 108 个合法字段场景，CI 同步执行。结果校验采用 `draft-07/flow-subset-2`，按设计限定关键词及明确注解实现，不包含完整 draft-07。

团队和作业测试使用 ContractHost 及真实文件存储，子进程验证历史读取。补充的固定版本官方 schema 实例中，309 项符合预期，含不支持关键词的 6 组、26 项未运行。该补充检查不代表完整规范认证。P4 仍需验证真实工具传输身份、材料权限和呈现，以及主会话通知。

领域变更以每个 Run 的原子快照提交。释放先缓存完成 Promise，再执行取消和通知；历史记录保留中断事实，旧运行句柄失效，新作业通过恢复来源建立新关系。七项旧控制器、排队作业及类型夹具测试已删除。

持久数据使用显式格式与版本外壳。正常归档查询不受无关坏文件阻断；无法确认目标不存在时报告读取不可用，损坏文件保留。读写共用完整 RunRecord 及嵌套字段的结构验证，读取不以强制断言跳过边界。


## P3 模板目录、编译与应用

[P3 验证记录](p3-verification.json)对应 C047–C052。合同共 472 项，其中前期 402 项、Core 创建隔离 15 项、模板 55 项；独立新增边界测试 13 项。目录、编译与纯展开采用设计的 count、use、groups/forEach，运行目录固定快照并隔离候选。坏包及依赖它的定义有诊断，其余定义可用。

应用先完整预检，再父先子后建立空闲成员及初始群。包内显式所有权门禁隔离未提交资源，释放与终止处理完整登记；失败只补偿本次新增对象。提交先确定成功，再冲刷历史观察事件，观察回调中的终止不会反转结果。

14 份参考包来自设计资源的同一份源码。真实 rc.2 Native 使用确定性模型夹具验证全员 idle、send=0、模型请求为 0；正文示例新增 12 名成员，参考 hierarchical 包另有 integrator，新增 13 名成员。tarball 的独立安装位置能默认加载全部 14 包，14 份资产逐字节相同，仅安装声明的运行依赖。

显式 preset/skills 的真实安装、默认 team-strategy 和原生工具身份由 P4 接入；P3 遇到未支持要求时在创建前拒绝。原本仅在本地的旧引擎与固定 execute 测试未被导入，不能计为 P3 新删除。

## 工单与停止原因

- [#93](https://github.com/Luohaothu/dsh-flow/issues/93) 记录宿主工具来源参数歧义与静默忽略身份。模型传入 `kind=user` 和核验成员 ID，工具接受后实际只匹配用户来源。核验回复约 161 秒后已成功发送，沟通成员直到约 600 秒超时才恢复。最终原生日志包含超时通知及随后接收成员通知的记录。共享 `source()` 转换影响多个工具，严格互斥和拒绝混合字段作为建议修复政策待分诊；不能称核心消息丢失或等待匹配失效。
- [#92](https://github.com/Luohaothu/dsh-flow/issues/92) 记录相交群的分段框体验。三成员群显示三个同 ID 标签，但整体包围盒会覆盖非成员卡片，符合现行设计的分段例外。首次按实现 bug 登记后已更正为待对齐事项，不据此判定 #24 的普通单群修复失效。
- [#90](https://github.com/Luohaothu/dsh-flow/issues/90#issuecomment-6541121736) 补充排期推断的来源核对问题。本轮只记录，不定向改提示或技能。

登记 #93 后，通过正常产品入口解散两个团队，并停止主会话生成。最终两份运行记录均为 `stopped`、`cleanup=complete`，没有未结束作业。两个官方进程正常退出，容器退出码均为 0。工作区、原生会话和日志保存后移除容器，关闭临时页面，没有本波进程继续运行。
